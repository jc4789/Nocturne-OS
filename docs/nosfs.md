# NOSfs：Nocturne の保存エンジン

設計の出発点は `D:\Programes\NOSfs.txt`。この文書は、実装が守る形式と規則を定める。

目標は「小さく編集したら小さく処理され、巨大なものも RAM へ閉じ込めず、保存中も操作できる」こと。

捨てるもの：

- ファイル全体をひとつのヒープバッファーに閉じ込めること
- 保存先によって別世界になること（RAM の `/` と FAT の `/data`）。`/` 全体が一つの永続ボリューム
- 保存途中の全文コピー
- 小さな変更の費用が、保存済みデータ全体の量に比例すること（全体チェックポイント、起動時の全走査）

## 1. 層

```text
アプリ（文書ハンドル：READ／EDIT／CREATE／REPLACE、保存の要求と完了イベント）
   │
vfs（文書 API、未公開版の作成・公開・破棄、保存の要求）
   │
名前空間 fs/ramfs.c ── RAM 上の木。フォルダーは開かれた時点で読み込む
   │       ├─ 不変の土台（initrd の書庫から作る、名前空間に出ない木）
   │       └─ ボリュームのフック（読込み、変更の記録、保存）
   │
内容エンジン fs/content.c ── 文書の版＝ページの集合
   │       ├─ RAM のページ、initrd の書庫ページ、媒体上の範囲
   │       └─ 版の重ね合わせ（作業版は確定版の上の差分）
   │
NOSfs fs/nos.c ── 索引（写し書きの B+木）、空き領域、確定、群確定、追い出し先
   │
ブロック層 dev/blk.c ── 書込み（write）と永続化（persist）を分けた要求
```

- `/tmp` は媒体を持たない別の木（再起動で空）。`/dev` も別の木。どちらも `/` にマウントする。
- FAT は交換用の媒体だけ（`/media/<ラベル>`）。
- `/data` は永続性の境界ではない。既存のアプリと PATH のための普通のフォルダー（`bin`、`etc`、`src`、`projects`）。

永続ボリュームが無い起動（置き場所の無い媒体）では、同じ木が媒体無しで動く。そのときは起動ログに「永続化されない」と出す。

## 2. ブロック層

- `write` は装置の揮発キャッシュへ届けるだけ。`persist` が揮発キャッシュを媒体へ書き出す（ATA FLUSH CACHE、NVMe Flush、SCSI SYNCHRONIZE CACHE）。前回の persist の後に何も書いていない装置には送らない（persist を始める前に戻った書込みは、必ずその書出しに含まれる）。
- 装置のブロック長（512／4096）と失敗数を `struct blkdev` が持つ。失敗は `-N_ERR_IO`（期限切れは `-N_ERR_TIMEOUT`）に正規化する。
- ファイルシステムは「どの書込みが、どの書込みより先に媒体に届いていなければならないか」を persist で表す。

## 3. 文書・確定版・作業版

- **文書**：名前が変わっても同じものを指す。RAM では vnode、媒体では ID。
- **確定版**：大きさとページが固定された内容。媒体の索引が指す状態と一致する。変更されない。
- **作業版**：確定版を土台にした、変更可能な内容。変えたページだけを持ち、残りは土台の版から読む。

ハンドルとの関係：

- READ は開いた時点の確定版を参照で固定する。後の保存で文書が新しい版になっても、最後まで同じ版を読む。
- EDIT と CREATE は文書の作業版を共有する。書込みは他の EDIT ハンドルにすぐ見える。
- REPLACE は文書とは別の、土台を持たない未公開版に書く。公開で文書の作業版がそれに置き換わり、確定へ回る。

**保存（確定）**：

1. 作業版を凍結する。文書には、凍結した版を土台にした空の作業版を付け直す（O(1)）。保存中の入力は新しい作業版に積まれ、保存済みには数えない。
2. 凍結した版の汚れたページを新しいブロックへ書き、索引の変更を作る。
3. 群確定（§6）が媒体に届いたら、凍結した版が新しい確定版になる。古い確定版を固定している READ がいなければ、両者を一つにまとめる（小さい方を大きい方へ移すので、費用は変更量に比例する）。

保存の失敗（媒体の故障）では、凍結した版は確定版にならず、次の確定でもう一度書かれる。後続の保存は、先行する保存を含めて媒体に届いたときだけ成功になる（確定は常に操作の順序の前方部分）。

REPLACE の公開先は、開いた時点の文書（ID）。その後に文書が移動されていれば移動先に保存し、元の名前に別の文書が作られていても、それを潰さない。開いた時点で文書が無く、公開時に名前が使われていれば `N_ERR_EXISTS`。

過去の版を永久に残すことはしない。現在の確定版、READ が固定した版、保存途中の版だけを持ち、不要になった時点で解放する。

## 4. 内容エンジン（fs/content.c）

文書の一つの版が `struct content`。

- **ページ表**：自分が持つページの 512 分木（一節点＝4 KiB の一フレーム）。項目は物理フレームと印（汚れ、参照済み、読込み中）。木は触れた範囲だけ育つ。
- **範囲表**：自分が持つページの媒体上の連続区間 {先頭ページ、ページ数、ブロック、印}。印は「未確定」（作業領域として逃がしたブロック）か「確定」。
- **土台の版**（`base`）：自分が持たないページは、`base_limit` より前なら土台の版から読む。土台の版が RAM に持つページはそのまま共有され、媒体から読んだページも土台の版のページ表に入る（版ごとに同じ内容を二重に抱えない）。
- **小さな内容**：512 バイト以下で土台もページも無い版は、ヒープ上のバイト列で持つ（4 KiB のフレームを使わない）。媒体では索引の項目の中に置く。
- **借用ページ**：initrd の書庫ページを読み取り専用で直接指す。書庫のページは誰も指さなくなった時点で割当器へ返す。
- **所有**：フレームとブロックは、それを表に持つ一つの版だけが所有する（共有は土台の連鎖で表し、参照数を数えない）。
- **追い出し**：媒体にあるきれいなページは、時計方式で追い出せる。
- **作業領域の退避**：作業版の汚れたページは、確定せずに媒体へ逃がしてフレームを返せる（未確定ブロック）。再び汚れて逃がすときは同じブロックへ上書きする。凍結した版のブロックと確定ブロックには上書きしない。電源断後、未確定ブロックは空きに戻る（索引が指していないため）。
- **汚れの上限**：媒体を持つ文書の汚れたページ（未退避）が上限を超えると、書き手は退避を待つ。RAM 容量を超える編集も続けられる。

## 5. ボリュームの形式

ブロックは 4 KiB。整数はすべてリトルエンディアン。すべてのブロックは CRC32C を持つ。

| 位置 | 中身 |
|---|---|
| ブロック 0 | ボリューム見出し |
| ブロック 1、2 | 錨（交互に書く） |
| 空き領域図（二組） | 空き領域の要約と、ブロックごとの使用ビット |
| データ領域 | 索引の節点、文書の内容 |
| 最終ブロック | ボリューム見出しの控え |

**ボリューム見出し**：識別子 `NOSfs`、形式の版、総ブロック数、ボリューム ID（作成時の乱数）、各領域の位置。作成後は変更しない。

**錨**：確定した保存状態の入口。世代、索引の根の位置と高さ、次の ID、空きブロック数、ボリューム ID、CRC32C。マウントは、検証できる新しい方の錨を読むだけで終わる。全体の走査はしない。

**索引**：写し書きの B+木一本。鍵は {対象 ID、種類、位置}。

| 種類 | 鍵 | 値 |
|---|---|---|
| 項目（ENTRY） | 親フォルダーの ID、名前の hash＋順番 | ID、種類、許可、大きさ、更新時刻、印、名前、土台での位置（引き取った項目）、小さな内容 |
| 範囲（EXTENT） | 文書の ID、先頭ページ | ブロック、ページ数 |
| 隠し（HIDE） | 土台での親の位置の hash、名前の hash＋順番 | 土台での位置 |

- 変更は、変わった葉から根までの節点を新しいブロックへ書く（写し書き）。古い節点のブロックは、その確定が媒体に届いてから空きに戻る。
- 一回の確定で同じ節点を何度変えても、書くのは一回。
- 節点は使われた分だけ RAM に読み込む。フォルダーの読込みは、その親 ID の範囲の走査。

**空き領域図**：図ブロック 1 枚が 32640 ブロックを表す（先頭 16 バイトが見出し、残りがビット）。各図ブロックと要約ブロック（図ブロックごとの空き数）は二つの置き場を持ち、確定のたびに古い方へ書く。見出しの世代が錨の世代以下で CRC が合う、新しい方が有効。図ブロックは使うときに読む。マウントで読むのは要約だけ。

## 6. 確定（群確定）

アプリの保存要求と名前空間の変更（作成、名前変更、移動、削除、属性）は、開いている取引に入る。確定担当のスレッドが、取引を閉じて媒体へ送る。

1. 取引を閉じる。以後の変更は次の取引に入る。閉じた取引の節点を変える必要が出たら、次の取引で写し書きする。
2. 閉じた取引の文書の汚れたページを、取引の中で割り当てたブロックへ書く。凍結した版は変わらないので、フレームから直接書く。
3. 汚れた索引の節点、変わった空き領域図と要約を書く。
4. persist。
5. 次の世代の錨を書く。
6. persist。
7. 保存の待ち手に結果を返す。解放待ちのブロックを空きに戻す。

- 待ち手（保存要求）があれば、確定担当はすぐに確定する。確定中に来た要求は次の確定にまとまる。要求が無くても、変更が約 1 秒たまったら確定する（補助）。
- 確定中も、アプリの編集と名前空間の操作は止まらない（次の取引に入る）。
- 置き換わったブロックは、確定が媒体に届き、それを表に持つ版（READ が固定した古い版）がいなくなるまで空きに数えない。

**回復**：二つの錨のうち検証できる新しい方を選ぶ。それが指す索引と空き領域図は、錨より先に媒体に届いているので、そのまま使える。

- 成功を返した保存は残る。
- 応答前に落ちた保存は、旧版か新版のどちらかになる。途中の混合状態にはならない。
- 未確定ブロック（逃がした作業領域）は索引に現れないので、空きに戻る。

## 7. 空き領域と予約

- 小さな書込みは前回の割当て位置の続きから、大きな書込みは連続した空き区間から割り当てる。
- 汚れたページは一ページにつき一ブロックを予約する。索引の写し書きの分を別に予約しておき、残りが足りなければ書き込みの時点で `N_ERR_NO_SPACE` を返す。確定の途中で容量が尽きて失敗することはない。削除と名前変更は、書込み用には使えない最後の予備で必ず確定できる。

## 8. 名前空間と不変の土台

initrd の書庫が、配布された OS の版（不変の土台）。起動のたびに、名前空間に出ない木として展開する（中身は書庫の上で読む）。

- フォルダーは、初めて開かれた時点で作る。中身は「ボリュームの項目」と「土台の同じ位置の子」の合成。
- ボリュームの項目と同じ名前の土台の子は見えない（利用者のものが勝つ）。HIDE がある土台の子も見えない。
- 土台の項目は、変更・移動・削除されるまで ID を持たず、索引に現れない。
- 最初の変更で引き取る：ID を与え、項目（ENTRY）を記録する。土台での位置を持つので、OS の版が変わっても同じ項目を指せる。その親も同じように引き取る。
- 移動・削除した土台の項目は、元の位置に HIDE を残す。新しい OS の版がその項目を持っていても、元の位置には現れない。HIDE は土台での親の位置で引くので、親のフォルダーが引き取られていなくても（ID が無くても）読込みで効く。
- 土台の文書の内容を変えて保存したときは、変えていないページも含めて文書の全ページを NOSfs のブロックへ書く（書庫から直接）。以後その文書は土台に依存しない。
- 名前を変えただけで内容に触れていない土台の文書は、土台の内容を読み続ける（OS の更新で中身も新しくなる）。
- GPU のファームウェアのように、機械に合わせて落とす土台の項目は、土台の木から落とす（利用者の削除として記録しない）。

## 9. 一つの媒体

```text
起動 USB／SSD
  ├─ 区画 1：FAT32「NOCTURNE」 … limine、カーネル、initrd（交換用。休止イメージは置かない）
  ├─ （OS の版が大きくなる分の余白）
  └─ 区画 2：NOSfs（MBR 種別 0x7F）… `/` の永続化
```

- 起動時、ドライバーがそろった後、init より前に NOSfs を探して `/` に結び付ける。
- 探し方：MBR の種別 0x7F の区画。無ければディスクの最終ブロックの見出しの控え。控えで見つかったボリュームが今の区画と重ならなければ、MBR の空き項目へ書き戻す（起動イメージを USB へ焼き直すと区画表は消えるが、後ろの NOSfs は残っている）。
- 区画・控え・作る位置の見出しのどれかが読めない、または見出しの印はあるのに検証できないときは「無い」とみなさない。そのディスクのボリュームを上書きしないよう、どのディスクにも作らず、`/` を永続化しないことを起動ログに出す。
- 無ければ作る。対象は Nocturne 自身のディスク（MBR 署名 `NOCT` の起動媒体、`DATA` の空のデータディスク）だけで、他のディスク（Windows の SSD など）には決して書かない。起動媒体では、最後の区画の終わりの 2 倍か 256 MiB 先の大きい方（1 MiB 境界）から始め、焼き直したイメージが大きくなっても重ならない余白を残す。64 MiB 以上取れなければ作らない。順序は、見出し・錨・空き領域図・空の索引・控え → persist → MBR の区画項目 → persist。作成時に `/data` とその `bin`、`etc`、`src`、`projects` を作る。
- 空のデータディスクは区画表の無い `DATA` 署名の MBR だけを持つ（`MKDATA_BLANK=1 scripts/mkdata.sh`、Hyper-V 用の `data-blank.vhdx`）。NOSfs はセクター 2048 から作られる。
- FAT の `NOCTDATA` は `/media/NOCTDATA` に交換用として付ける。NOSfs を置ける場所が無い起動（区画全体が FAT の古い Hyper-V のデータディスクなど）に限り、移行用として従来どおり `/data` に付け、そのことを起動ログに出す。
- 名前は大文字・小文字を区別する。

## 10. アプリから見た保存

- `n_document_commit(h, N_COMMIT_WAIT)`：ハンドルの版を保存し、媒体に届くまで待つ。書いていない書込み用ハンドルでは、その文書のそれまでの記録（作成、名前変更、別のハンドルの保存）が届くまで待つ。読み取り専用のハンドルは待たない。
- `n_document_commit(h, N_COMMIT_START)`：保存を始めてすぐ戻る。届いたら、待ち行列で監視していれば `N_EVENT_SAVED` が報告される。
- `n_document_commit(h, N_COMMIT_RESULT)`：最後に始めた保存の結果。まだ届いていなければ `N_ERR_NOT_READY`。結果を読むと `N_EVENT_SAVED` は報告されなくなる。
- REPLACE ハンドルの保存は公開を兼ねる（公開した版はすぐに名前空間で見える）。保存した REPLACE ハンドルは読み取り専用になる。公開できたが保存を断られたときは、ハンドルは書込み用のまま残り、もう一度の保存がその版を保存する。公開の前から保存の完了を待っていた監視は、公開された文書の監視に移る。
- `n_handle_close` は、書いたハンドルを保存して待つ（従来どおり）。`n_document_save` は REPLACE を開き、書いて、待つ保存をする薄い包み。

## 11. 休止

休止イメージは、ファイルシステムに依存しない「動かない予約領域」に書く。

- `reserve(v, size)`：空の文書に、誰も書いていないブロックを割り当てる。確定済みの版として記録されるので、回復後も位置は変わらない。
- `extents(v, run, ctx)`：その文書の媒体上の区間を、装置のセクター単位で順に返す。

休止の書込みと読戻しは、この区間へブロック層で直接行う。NOSfs でも FAT でも同じ手順になる。

- それまでの保存は、休止に入る前（ブロック層を押さえる前）に媒体へ届ける。押さえた後の確定は媒体に届かずに待ち、スナップショットの後は何も確定しない。イメージは、その待っている確定ごと機械を持ち、復帰してから確定する。
- 電源断と再起動では、アプリを止めた後に保存を媒体へ届けてから切る。

- 休止イメージは `/data` を記録しているボリュームに置く。`/data` がどのボリュームにも記録されていなければ休止しない。
- USB ディスクが挿さっている間は、従来どおりスリープも休止もしない（`xhci_refuse`）。復帰時に xHCI は列挙し直すので、USB ディスクは新しい装置として戻り、付いているボリュームの下の装置が入れ替わる。USB から起動した `/` で休止するには、列挙し直したディスクを元の装置へ結び直す必要がある（未実装）。

## 12. 実装の段階

1. ブロック層：write と persist の分離、ブロック長、失敗の報告。（済）
2. 内容エンジンと stage／publish、全文コピー無しの保存・移動。（済）
3. 版の重ね合わせ（確定版・作業版・凍結）、小さな内容、作業領域の退避。（済）
4. NOSfs：索引、空き領域図、群確定、予約、追い出し、確定担当。（済）
5. 名前空間：遅延読込み、不変の土台の合成と引き取り、`/tmp`・`/dev` の分離、FAT の `/media`。（済）
6. 起動媒体での区画の作成と再発見。（済）
7. 保存の完了イベント（ABI）。（済）
8. 休止の予約領域を vnode 操作へ移す。（済）

後回し：永久履歴、重複排除、実行中の圧縮、永続オブジェクト（文書のページをアドレス空間へ割り当てる）、OS の版の更新と利用者の変更の衝突の表示。
