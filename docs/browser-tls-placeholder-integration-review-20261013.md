# TLS待機・placeholder統合の主担当確認

TLS担当の第一・第二報、tls.cのio_begin/io_timeout、TCP開始からTLS確立へのdeadline、public readのrecord反復、EOF/errno保持、key wipeとcloseを主担当が独立して読んだ。本文の長時間read/-1を接続確立と区別し、満杯TX内tcp_sendの無期限境界は未保証として残す。100秒の成功取得をこの修理で高速化したとは主張しない。HTTPの既存inner共有、timing集計とprivate header検証・callback前除去も確認した。

placeholder担当の第一・第二報とCSS selector/cascade/非継承clear/input描画を確認。追加のcached pointerは作者一致するtext input/textareaだけ計算し、paint時の全CSS走査を増やさない。入力値の描画・caret/selectionは元control styleを使う。主担当はgetComputedStyleの無視されていた第二引数を既存CSSStylePropertiesへ接続し、cached疑似styleとUA stack fallbackの読取・custom property列挙・未知疑似の空declarationを実装した。元24条件を保全し、20疑似CSSOM条件を追加。

完全buildと最新媒体のnative/実サイトはこれから確認する。host支持、構文、他担当の報告を実サイトの左欄復旧・二重表示解消・性能回帰解消へ昇格しない。

初回完全媒体のnativeは失敗した。paint12条件中7失敗、CSSOM追加条件も作者色がUA灰色のままで失敗。既存内部PE_SLOTTED macro=5と新共有PE_PLACEHOLDER=5の衝突により、placeholder宣言が通常controlへ誤配達されていた。担当が共有enumの非衝突値へ製品修理中。初回host14成功とreviewをこのnative失敗へ優先しない。原失敗ログはbuild/browser-tls-placeholder-native-20261013/test-serial.logに保全する。

直近実画面：Reddit左欄空・二重placeholder、DuckDuckGoの丸検索欄/フィルターinline/丸avatarは原画で確認。Redditの正MIME200後TypeErrorはxr→br→_renderContentの公開source位置へ絞った。旧VMでのconsole source読取はfocus/期限終了により一部未成立。数値なしで全site性能改善を主張しない。

容量：停止・PID非生存とbuild内の解決済pathを確認して、本区間の旧VM11個のboot/data一時コピーを回収した。原画・serial・metadata・hashは保全するが、削除媒体をそのまま再実行可能とは書かない。通常data、最新IMG/VHD/VHDX/ISOとHyper-V媒体は触っていない。
