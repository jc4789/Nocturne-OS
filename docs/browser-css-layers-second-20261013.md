# Cascade layer／文字省略：別の第二考察

第一報を変更せず、「font shorthandを直せばAboutが小さくなる」という仮説を棄却した。原値を既存parserで計算すると16pxになるため、原因はfont containerや字体ではない。precedenceがspecificityより前にある層をflattenすることが、原DOM／CSSと24pxの共通境界だった。

最弱前提は共有ASTにdocument-wide layer番号を付ける案である。adopted sheetが別shadow rootや別文書で使われると、初出順とscopeが違う。immutable syntaxから文書・scope別 registryを作り、各bindingに対応表を持たせた。匿名層は同じASTを別instanceで使っても別のidentityとなる。workerは完成したregistryを読むだけ。

importsを単純にpostorder style vectorで宣言順にすると、親の先行statementより子のlayer初出が先になる。docの実import所有関係とparser eventを使い、親eventの位置で子へ入るiterative walkにした。失敗／取消／rescan／redirectのCSS要求identityは先行修理の所有を維持し、layer orderingのために再取得しない。

importantの層逆順だけでも不十分で、inline importantは層に負けてはいけない。encapsulationとanimationも先に比較し、層は同origin/contextの条件でspecificityより前に比較する。revert-layerは単なるunsetではなく、現在層とimportant/normalの間の候補を除外する。inline importantのrollbackはauthor important全体を消さず、style属性とintervening animationに限定する。custom propertyとfont-size先行pass、shorthand/allも同じrollback境界を使う。

長いページの通常cascadeで、rollbackを一つも使わないのに毎nodeの配列をzeroするのは新たな性能回帰になる。初期化とlonghand mask走査を実rollbackに限り、通常は従来css_applyへ直行する。稀な新機能をhot pathの恒常費用にしない。

child-listの旧失敗は、古い一致を保全する保守候補が広すぎた反例である。`:not(:empty)`のrightmostはouter subjectと同じ要素だから、outerのclass/id/tag制約を捨てない。一方、logical complex selectorの左側は別要素なので独立候補を残す。親全descendantの継承／var／明示inherit／arena retirementと既存has witness無効化は省略していない。

text-overflowは解析だけの成功ではない。親が必要要素だけlineをretainするためclip→ellipsisで内部再layoutが必要となる。layout-equality除外を取消し、論理run/DOM寸法/scrollareaを変えず実markerのpaintと接続する。host40件はgrammarと非継承の証拠で、未完成のpaintや実サイト受入へ昇格しない。

次は最新native新条件と原WPTの失敗を読み、同じ未変更成功群を反復せず、製品の失敗境界を修理する。文書全体成功・性能改善・無回帰はまだ未確定。
