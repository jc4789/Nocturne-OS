## 決まり（00-design.md §3 の要点）
- 持ち主の単位で消してから建てる。古い道を残して新しい道を足さない。shim（何もしない関数、渡すだけの包み、偽の環境）を作らない。名前だけの口を作らない。
- 決め打ちの上限を置かない（表の大きさは実際の数から。ハードウェアが決める数は出典つきで定数）。時間の定数は仕様の値か測った値で、出典を注記に書く。待ちは割り込みか事象で起こされる形にし、決まった間隔の見回りや回数の spin を作らない。
- 自分の持つファイルの外は、設計の節が「触ってよい」と書いた所だけ、口を変えるための最小の行だけ。それ以外の持ち物に触れる必要が出たら、触らずに報告に書く。
- コードの注記は周りに合わせて英語。今あるコードの書き方（名前、注記の濃さ）に合わせる。
- 編集は Edit・Write で。シェルや Python でファイルを書き換えない（この Windows の Python は LF を CRLF に変える）。シェルは Bash（Git Bash）。探すのは `rg`。
- 組んで確かめる：あなたの作業木の根で `python -X utf8 scripts/build.py -j 8 kernel`（出力は本体の `build/wt/<作業木の名>/` に行く）。警告を増やさない。QEMU は起こさない（本体の会話が、取り込んだ後に起動して確かめる）。媒体（img）は作らない。
- 作業木の枝にコミットする（題は日本語で「段 1-<名>：何をしたか」、本文の最後に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`）。main へ取り込まない。push しない。
