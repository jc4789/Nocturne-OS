# Nocturne の根の設計：境界・持ち主・設定（案、2026-11-01）

監査の全文：`docs/settings-audit-kernel-20261101.md`、`docs/settings-audit-user-20261101.md`、`docs/settings-audit-boundaries-20261101.md`、`docs/settings-audit-external-20261101.md`。
この案は承認の前の案である。承認までコードを変えない。

## 1. 法

持ち主の言葉を法とする。

> UNIX・Linux の設定の扱いは禁止。全部をファイルにしない。境界は UI、システムのプロセス、カーネル。編むファイルは無く、変えて適用する設定がある。

法から次の規則が出る。

1. 文書は利用者の内容とプログラムのデータである。文書は設定、通信、装置、身元、権限、登録、動作の切替えではない。
2. 値は四つのどれかである：仕様の定数、装置の申告、利用者の選択、機構が計算した値。ほかの決め打ちは欠陥である。
3. カーネルは方針を持たず、利用者を知らず、絵を描かず、文を話さず、文字列の設定を解析しない。
4. UI は値を持たず、装置に触れない。
5. 能力、選択、実効は別の物で、別の持ち主を持つ。
6. 権限は持ち主の入口で確かめる。確かめの材料はカーネルが証明する。

## 2. 三つの層

| 層 | 持つ物 | 持たない物 |
|---|---|---|
| カーネル | CPU、記憶、割り込み、object・handle・channel、C: の格納、装置の取り合いと driver の機構、身元の運搬、能力の申告、実効の報告 | 既定の選択、利用者、文、窓、絵、キーの割当て、保存する設定 |
| システムのプロセス | 領域ごとの方針、選択の保存、適用の順、アプリの登録、セッション、ログの保存 | 絵、利用者との対話 |
| UI | シェル（タスクバー、メニュー、通知、デスクトップ）、設定の窓、ログインの窓 | 値、保存、装置 |

「GUI が先」は優先の話であり、特権の話ではない。UI は第一級の品質で、カーネルの外で動く。性能の保証は締切の級、共有の記憶、直接の scanout という機構で渡す。

### 2.1 カーネルに残す物と、出す物

| 領域 | カーネル（機構） | システムのプロセス（方針） | UI |
|---|---|---|---|
| 音 | 音の driver（HDA、USB Audio）、DMA の輪と位置、装置の形式の一覧 | `audio`：混合、変換、出口の選択、音量、流れの受付 | 音の頁、タスクバーの音量 |
| 画面 | scanout、flip、vblank、共有の面、モードの一覧、EDID | `display`：モードの選択、配置、主画面、倍率、試行と戻し。`compositor`：窓の順、焦点、合成 | 画面の頁 |
| シェル | なし | `session` が起こす | `shell`：タスクバー、メニュー、絵、字、文 |
| 入力 | HID の装置、物理キーの usage と相対量の輪 | `input`：配列、繰返し、加速、近道の配達 | 入力の頁 |
| 網 | NIC の driver、IP・TCP・UDP、adapter の一覧 | `network`：DHCP、DNS、固定の住所、経路の選択、proxy | 網の頁 |
| 電源 | 眠り・再起動の実行、ACPI の事象の報告 | `power`：方針、窓を閉じる段取り、放置、ボタン、蓋 | 電源の頁 |
| CPU | スケジューラーの機構、性能の要求の口、idle の機構 | `power` と `session`：性能の好み、アプリの重みの方針 | 性能の頁 |
| 利用者 | process の身元の欄 | `session`・`accounts`：利用者、ログイン、切替え | ログインの窓 |
| アプリ | 起こす機構 | `apps`：登録、既定のアプリ、種類の対応 | メニュー、既定のアプリの頁 |
| driver | PCI の claim の機構 | `services`：driver の対応、起動、起こし直し | 装置の頁 |
| 時刻 | UTC の時計、RTC の読み書き | `time`：時間帯、時刻の同期 | 時刻の頁 |
| ログ | CPU ごとの輪 | `log`：機械の場所へ保存 | ログの窓 |
| 秘密 | なし | `secrets`：API の鍵、証明書の信頼 | 資格情報の頁 |
| RDP | なし（`vm/` の裏の装置だけ） | `remote`：接続の protocol | なし |

C: の格納と TCP/IP はカーネルに残す。理由は性能と、起動の順の単純さである。これは今回の範囲の判断で、機構に限り、方針を持たせない。

## 3. 設定の模型

### 3.1 一つの設定の形

設定は次の欄を持つ object である。

| 欄 | 中身 | 持ち主 |
|---|---|---|
| 鍵 | 領域と名前の組。番号で引く型つきの id | 領域の宣言 |
| 型 | 真偽、整数と範囲、列挙、文字列、一覧、記録 | 領域の宣言 |
| scope | 機械、利用者、装置、機械上の装置ごとの利用者、プログラム | 領域の宣言 |
| 既定 | 値か「装置に従う」 | 領域の宣言 |
| 能力 | 今選べる物。形式の組の一覧のような積の形も表す | 装置の申告を領域が束ねる |
| 選択 | 利用者か管理者が選んだ物。無ければ「選んでいない」 | 設定のサービスが保存 |
| 実効 | 今それで動いている値 | 領域が報告 |
| 適用の級 | すぐ効く、装置を開き直す、セッションの入れ直し、再起動 | 領域の宣言 |
| 状態 | 動いている、装置が無い、適用に失敗、管理者が固定、領域が止まっている | 領域と設定のサービス |
| 表示 | 題と説明の文の id。文は領域の言語の資源にある | 領域の宣言 |

選択と実効が違うことは普通に起こる。装置を抜いた時、装置が値を受けない時、管理者が固定した時である。三つを別々に見せる。

### 3.2 値を引く順

実効を決める元の順は次のとおりである。

1. 管理者の固定。
2. 装置ごとの利用者の選択。
3. 利用者の選択。
4. 装置ごとの機械の選択。
5. 機械の選択。
6. 領域の既定（装置の申告から計算してよい）。

装置は順の番号でなく、安定した身元で引く。USB は vendor、product、serial と、serial が無ければ接続の道。画面は EDID。PCI は vendor、device、subsystem と場所。

### 3.3 変更の段

変更は一つの手順である。全部の設定が同じ手順を通る。

1. **問う（validate）**：領域が、変えずに通るかを答える。
2. **試す（try）**：領域が実効を変える。保存しない。戻す札を返す。
3. **残す（commit）**：設定のサービスが原子的に保存する。
4. **戻す（revert）**：領域が前の実効へ戻す。
5. **知らせる（notify）**：何が変わったかを、鍵と新しい実効で知らせる。

- 複数の鍵を一つの変更にできる（画面の配置と複数のモード）。
- 確認が要る設定は、領域が期限を宣言する。期限の秒読みはサービスが持ち、UI が死んでも戻る。
- 「すぐ効く」設定の試すと残すは一度に進む。音量の滑り棒はまとめて送り、最後の値を残す。
- 値が通らなければ、理由の id を呼ぶ側へ返す。黙って捨てない。
- 保存の失敗も呼ぶ側へ返す。

### 3.4 設定のサービスと領域のサービス

二つの持ち物を分ける。

| | `settings`（一つ） | 領域のサービス（領域ごと） |
|---|---|---|
| 持つ | 選択の保存、宣言の表、型と範囲の確かめ、権限の確かめ、見張り、変更の段の取りまとめ、管理者の固定 | 能力、実効、適用、領域の既定の計算 |
| 持たない | 領域の意味、装置 | 保存、窓、利用者の確かめ |

- UI とアプリは `settings` だけに話す。領域のサービスは `settings` からの適用だけを受ける。受ける口の handle は `settings` しか持たない。
- 領域は起動の時に宣言を出す。設定の窓は宣言の表から頁を組む。設定を一つ足すのに変える場所は領域の宣言と適用の二つだけである。画面の配置のような特別な頁は、領域が UI の部品を添える。
- `settings` は鍵の意味を知らない。神のサービスにしない。
- 領域が死んだ時、その鍵は読めるが状態は「止まっている」になる。起き直した領域へ選択を渡し直す。
- `settings` が死んだ時、領域は実効のまま動き続ける。`services` が起こし直し、領域は宣言を出し直す。

### 3.5 保存の場所と形

- 選択の保存は、C: の名前の木に入らない。パスが無い。アプリにも利用者にも見えない。
- 格納の層に、名前の木の外の私的な領域を足す。開く手段は起動の時に渡す handle だけで、カーネルが `settings` の起動に渡す。
- 形は `settings` の中の版つきの二進の記録で、原子的に差し替える。編む道も文の形も無い。壊れていれば前の版へ戻り、利用者へ知らせる。
- 機械の値は機械の領域に、利用者の値は利用者の領域に置く。`AppData\Nocturne\*.conf`、`keep.c`、`older[]` の引き継ぎは消す。互換は持たない。

### 3.6 プログラムの設定

- プログラムの設定はプログラムの物である。共有の文書を作らない。
- OS は同じ模型の口をプログラムに渡す：scope「プログラム」、型、既定、見張り。プログラムどうしは互いの値を読めない。
- 移植したプログラムは自分のデータの場所に自分の形を持ってよい。それはそのプログラムの中身で、OS の設定ではない。OS はその形を知らない。
- `n_settings`（環境変数の形）の語を消す。起動の属性は型のある欄にする。環境変数は移植のための libc の中だけに置き、カーネルは名前を知らない。

### 3.7 起動より前の値

早い段階で要る物（IOMMU の方針など）のために、型のある小さな起動の記録を置く。

- 記録は loader の module で、機械の `boot` 領域が権限のある口で書く。利用者は設定の窓で変える。
- 手で編む文字列の cmdline を設定の道として消す。試験の旗は試験の組みだけに置き、製品のコードに読み手を残さない。
- loader の項目は「Nocturne」と「安全な設定で起動」の二つにする。後者は記録も選択も読まずに、領域の既定で起こす。`nogui` は消す。
- `limine.conf` は loader の中の事で、利用者の道ではない。

## 4. 身元と権限

1. **身元。** カーネルは process に身元の欄を持つ：利用者、セッション、プログラム。身元は親が子へ、権限のある口を通して渡す。アプリは書けない。
2. **相手の証明。** channel の受け手は、送り手の身元をカーネルから受け取る。
3. **能力。** 特権は handle である。`pid == init_pid` と `appdrivers=any` を消す。PCI の claim、電源の実行、画面の読取り、設定の適用の口、起動の記録の書込みは、それぞれ能力の handle を持つ者だけが使える。
4. **能力の道。** `services` が manifest に沿って handle を渡す。どのプログラムも、渡されなかった能力に触れない。
5. **名前。** channel の名前の早い者勝ちを消す。プログラムは起動の時に渡された `services` の channel から相手を引く。
6. **確かめの場所。** 設定を変えられるかは `settings` が入口で確かめる。領域は確かめ直さない。領域の口は `settings` しか持たない。

## 5. 起動の順

1. カーネルが機構を起こす。画面は firmware の面、音は止まったまま、網は上がらない。カーネルは既定の方針を選ばない。
2. カーネルが `services`（今の `init` を作り直した物）を起こし、全部の能力の根を渡す。
3. `services` が `log`、`settings`、領域のサービス、`session` の順に、manifest の依存で起こす。死ねば起こし直す。
4. `session` が機械の値でログインの窓を出すか、選ばれた利用者で入る。
5. 利用者が入ると、`settings` が利用者の層を重ね、変わった鍵を領域へ知らせる。
6. `session` が `compositor` と `shell` を起こす。

## 6. 領域ごとの形

### 音

- driver は装置の形式の全部を申告する：率の集合、bit の幅、container、channel、出口の種類、接続の状態。HDA は 7.3.4.7、USB Audio は 1.0・2.0・4.0 の記述子と要求から読む。
- `audio` は出口ごとに、混合の形式（率、bit、channel）を持つ。既定は装置の申告から決める。利用者は Windows の画面と同じく、装置ごとに選ぶ。`AUDIO_RATE`、`AUDIO_FRAME`、`N_AUDIO_RATE` を消す。
- アプリの流れは形式を宣言して開く。`audio` が混合の形式へ変換する。流れの本体は共有の輪で運び、呼出しの往復を増やさない。
- 排他の道を設定と権限で渡す。
- 音量は出口ごとに持つ。`wm_taskbar_changed` の呼出しを消す。
- 音量の曲線、選んだ出口、既定の役割は設定である。
- `audio` が死んでも driver は止まらず、起き直した `audio` が開き直す。
- USB Audio はこの形の上の driver の一つである。

### 画面

- カーネルは画面の一覧とモードの一覧（解像度、拍、色深度、色の形式、VRR）を渡す。
- `display` が選び、適用し、試して戻す。`screenmode.c` の `pick` と `trial_watch` はカーネルから消える。
- 倍率、配置、主画面は設定である。
- `compositor` は締切の級で動き、共有の面を合成し、flip の機構を使う。全画面の窓は直接の scanout を使う。GPU は `gpu` の driver のプロセス（実機は nvrm）にある。

### シェル

- `wm.c` のタスクバー、メニュー、音量の panel、toast、`desktop.c` の絵は `shell` へ移す。文はカーネルから消える。
- アプリの一覧は `apps` の登録から来る。

### 入力

- カーネルは HID の usage を渡す。PS/2 の scancode への変換と US の表を消す。
- 配列、繰返し、加速、ダブルクリック、スクロールの向きは `input` の設定である。装置ごとに持てる。

### 網

- DHCP、DNS、cache は `network` へ移す。カーネルは adapter の一覧と、adapter ごとの住所の適用の口を持つ。adapter が一つの形（`n_netinfo`）を消す。
- socket の形の呼出しは、Nocturne の handle と事象の形へ揃える。

### 電源・CPU

- 蓋、ボタン、放置、眠りの可否は `power` の設定である。カーネルは事象を知らせ、実行する。
- 性能の好みの関数に呼び手を作る。

### 利用者

- `C:\Users` の最初のフォルダーを利用者とする形を消す。`accounts` が利用者の一覧を持つ。自動で入る設定も選択である。

### 時刻・言語

- カーネルは UTC だけを持つ。時間帯、言語、地域、書式は設定である。libc と JS は `settings` から読む。

### 上限と調律

- 監査の M・D・X の項の固定の値は、装置に問うか、機構が計算するか、領域の設定にする。項ごとに表で決める。

## 7. 機械で守る

規則だけでは破られる。ホストの検査を足す。

- `tests/check_boundaries.py`：カーネルの include の方向、`cmdline_has` の読み手の許可表（試験の組みだけ）、カーネルの中の `.conf`・`store_save` の設定の使用、`dev/` から UI への呼出し、`pid ==` の権限の比較を拒む。
- `tests/check_settings.py`：宣言の表と適用の口が揃うか、鍵の重複、既定の型、文の id の有無を調べる。
- 決め打ちの新しい定数には、四つの種類（仕様、申告、選択、計算）のどれかを注釈で求め、検査する。

## 8. 段（悪いコードを消してから建てる）

各段の終わりに、組む、試験を回す、QEMU で同じ条件の fps と実時間を測る。性能の退行は失敗である。

| 段 | 中身 | 消す物 |
|---|---|---|
| 0 | 法と規則の書き直し（ユーザーの承認の後）、境界の検査を足す | 規則の誤った行 |
| 1 | 身元、相手の証明、能力の handle、`services`、名前の引き方 | `init_pid` の比較、`appdrivers=any`、名前の早い者勝ち |
| 2 | `settings`、私的な保存、模型の ABI、`n_settings` の改名、宣言から組む設定の窓 | なし（土台） |
| 3 | 音：driver の申告、`audio`、形式つきの流れ、USB Audio | `AUDIO_RATE`、`audio.c` の混合と音量、`Sound.conf` |
| 4 | 入力・電源・時刻・言語・ログ・秘密 | US の表、`pm.c` の文と段取り、`Desktop.conf` の速さ |
| 5 | 網 | カーネルの DHCP・DNS、`dns-server=` |
| 6 | 画面と `compositor` と `shell`（一番大きな段） | `kernel/src/gui/`、`SYS_WIN_*`、`SYS_SCREEN_INFO`、`keep.c` |
| 7 | 利用者とログイン、アプリの登録、既定のアプリ | `store_user_folder`、`USERFOLDER`、`SYS_GUI_LAUNCH`、`find_program` の走査 |
| 8 | 起動の記録と cmdline の削除、残りの上限と調律、`vm/rdp.c` の外出し | `cmdline_has` の製品の読み手、`nogui` |

途中の段では、古い道と新しい道が同時に動く期間を作らない。領域ごとに一度に切り替える。

## 9. この案で決めていないこと

ユーザーが決めること：

1. 窓の管理と合成をカーネルの外へ出す（段 6）。私の勧めは出す。性能の退行が出れば機構を足して直し、中へ戻さない。
2. C: の格納と TCP/IP をカーネルに残す。私の勧めは今回は残す。
3. 最初から複数の利用者とログインを入れる（段 7）。私の勧めは入れる。
