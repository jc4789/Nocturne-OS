## 作り直しの段

作り直しは手術のように段で進める。

1. 診断：何が悪いか、どこまでつながっているかを読む。範囲は問題が決める。消す範囲と建てる形を書けたら終わる。報告があれば読み直さない。
2. 計画：消す範囲、建てる形、閉じる段で見ることを見せる。「はい」の後に切る。
3. 消す：悪いコードを先に消し、新しいコードの場所を空ける。
4. 建てる：新しいコードを書く。
5. つなぐ：呼ぶ側を新しい形へ直す。
6. 閉じる：全部の段の後に、計画に書いたことを一度見る。直っていなければ撮り直さず、読んで直す。

- 段の途中は、ビルドが通らなくてよい。OS が動かなくてよい。
- 悪いコードを動かしたまま、その上に新しいコードを足さない。
- 段の途中の状態を確かめの理由にしない。組みの誤りは、つなぐ段で呼ぶ側の一覧として使う。
- 一つの不具合の修理に段は要らない。

## 完了

仕事は次で終わる。

1. 持ち主の層で直した。
2. 置き換えた古い道、特例、呼ばれなくなったコード、その試験を消した。古い名を `rg` して 0 件であることを報告に書いた。
3. 動きが変わる仕事は、製品を一度見て、見た範囲を書いた。
4. 足した行数と消した行数を報告に書いた。

- 同じ部品の修理が 3 本続いたら、次の修理を書かず、部品の設計を書き直して見せる。

## 規則

1. 整形は `clang-format`。一行に文は一つ。
2. 関数は一つのことをする。60 行を超えたら責務を問う。数合わせで分割しない。
3. 名前は検索で一意にする。一つの物に一つの語を使う。
4. 名前に作業の段の番号、`_new`、`_old`、`_v2` を入れない。
5. 呼出しは名前で書く。関数の表は本物の継ぎ目だけに使う。
6. 型で語る。意味を `int`、`void *`、文字列で運ばない。
7. enum の `switch` に `default` を書かない。増えた値を組みが教える。
8. 道は一つ。古い道、旗の切替、失敗時の代わりの道を持たない。
9. 失敗を隠さない。信頼の境界で全部確かめて理由を返す。
10. 内側の「起きないこと」は `ASSERT` にする。失敗に偽の成功を返さない。
11. コメントはコードに書けないことだけ：仕様の節、錠の順、なぜこの形か。
12. コメントに経緯、作業の段、「まだ」、「〜の持ち主」を書かない。
13. 関数には呼ぶ側、値には読み手、設定には効く先がある。仕事の範囲の中で、無いものは消す。
14. 同じ本体を二か所に置かない。短い関数も写さない。
15. 試験を書くなら、公開の口で、外から見た振る舞いを試す。
16. 試験で内部の関数の本体を切り出さない。コードを消したら試験も消す。
17. 一度きりの確かめは作業場に置く。リポジトリに入れない。

## 悪い形と代わり

## ハードウェアの抽象化の層（HAL）

機械はどれも同じではない。ハードウェアは HAL の後ろに置く。

1. 装置の種類ごとに契約を一つ持つ：CPU、割り込みと時計、バス、IOMMU、GPU、画面、音、ストレージ、網、入力、USB、電源と温度。
2. 契約の上のコードは、製造者、機種、世代を知らない。
3. 違いは実装の申告で受ける。上は申告で道を選ぶ。
4. 実装は契約の後ろに置く。実装を足しても、呼ぶ側は変わらない。
5. VM の装置も実装の一つ。
6. 契約を最小公倍数にしない。ハードウェアが持つものは、有れば使い切り、無くても動くように作る。
7. 契約の形を一社に合わせない。形は仕様書から作る。
8. 必須の機能の表の行には、それが無いと動かないコードがある。
9. 製造者の違いは製造者ごとの実装に置く。一つのファイルに製造者の分岐を集めない。

## 4. 道具

自信は情報と道具から来る。道具は止めるためでなく、知るためにある。機械へ移した文は `AGENTS.md` と規則から消す。

1. コンパイラー：`-Wno-unused-function` を外し、`-Wswitch-enum` を足す。消すと呼ぶ側と死んだ関数を教える。`ports`、`third_party` は対象にしない。
2. `make check`：検査を一度に走らせる別の目標。組みの前提にしない。作り直しの閉じる段で一度走らせる。`-Werror` はここだけで使う。
   - 止める検査：層の依存、製品の名前、`test_flag` の場所、段の番号の名、共通コードの `hypervisor`。今の違反は一覧に凍結する。
   - 数だけ出す検査：呼ばれない関数、写しの行数、関数の長さ、読み手の無い設定、呼ぶ者の無い syscall。
3. `clang-format`：`.clang-format` を置く。上流は除く。
4. ABI の一覧：`SYS_*` から、カーネルの処理、libc の包み、呼ぶ側までを出す。codegraph の索引に出ない道を埋める。
5. QEMU の操作の道具：起動、撮影、キー、クリック、ログ、止めるを、それぞれ一つの命令にする。一度見る費用を下げる。動くかどうかは道具でなく、見た者が決める。
6. `docs/open.md`：開いている所見と既知の欠陥の一覧。一行に一件。直したら行を消す。前から壊れていた物と、自分が壊した物を分けるために使う。
7. 走らない試験を整理する。試験の媒体を組む目標を一つ作る。
