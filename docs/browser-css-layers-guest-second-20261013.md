# 層・CSS資源：独立の第二考察

第一追加報の「色成分は既に正しい」という最初のassert結果を、層全体の合格に昇格させない。原basic/importantは最初のtargetの直列化で停止するため、第二targetのspecificityやnamed nestingの反例が隠れている。mediaも500pxへの変更前に止まる。次の確認では原assertをそのまま使い、期待値変更・除外・skipをしない。

data importをHTTP hostへ渡さない修理について、decoder返却bufferのallocatorを独立に追った。script_data_sourceとscript_blob_sourceはjs_malloc、pending_freeはjs_free、doc_css_loadedは別のmallocコピーである。doc CSS storageへ返却bufferを直接移す変更は避けた。文書破棄時もpendingを解放してからJS contextを破棄する現経路を保つ。data/body文字列を診断へ無制限出力しない。

同名font-face/keyframesは層順位をCSS宣言だけに付ける設計の反例だった。immutable syntax layerを各scopeのbinding registryへ対応させ、named resourceもnormal優先とsource順で選ぶ。unicode-range compositeは順位付きchoiceへ接続し、shared adopted ASTへ文書mutable順位を埋め込まない。native named5件の成功は既存opacity animationとフォント選択の範囲であり、未対応の色keyframes全体の成功ではない。

CSSOMはトップ階層insert/delete/replaceとshared adoptionを実装したが、既存CSSRuleListのnative子AST／CSSGroupingRule／CSSLayerBlockRule nested mutationは未対応。専用classだけ公開して本物の子所有・無効化が無い状態を作らない。新動的11件も未実行なので成功報告しない。

旧fixtureのopaque RGBA期待（mediatest／semantic elements）は現CSS Color4に反するため、同じ色成分を保ったrgb期待へ訂正する必要がある。これは原WPTを弱めることとは異なり、原WPTは変更しない。半透明alpha丸めやCSS MIME、Window named accessはそれぞれ別の共通境界として修理と確認を分離する。

静的整合は実表示、実マウス、上下スクロール、性能の証拠ではない。sourceと実行媒体の一致は主担当が新buildで確認し、nav表示の緊急受入を層の未確認結果で置き換えない。
