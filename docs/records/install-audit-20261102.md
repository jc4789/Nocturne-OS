# プログラムのインストール：今の形と足りないもの（2026-11-02）

## 結論

- Nocturne に「インストール」という考えは、今はありません。
- 第三者のプログラムを後から入れる道は、管理者が手でファイルを置き、設定の窓に名前とパスを打つことだけです。
- 第三者のプログラムが、自分のサービスを登録する道はありません。動いている間だけ名前を持てるだけです。
- 配る形式、インストーラー、アンインストール、更新、署名はありません。
- 一番深い問題は、形式が無いことではありません。プログラムが syscall の番号を直接持ち、OS と一緒に入るシステムのライブラリーを読む道が無いことです（欠陥 1）。形式を先に作っても、配ったものは次の OS の更新で壊れます。
- 部品はかなり揃っています。台帳のサービス、実行時の設定の宣言、サービスの管理者、原子的な文書の差替え、DEFLATE、TLS の暗号があります。足りないのは、これらをつなぐ設計です。

この調べはコードを読んだだけです。動かして確かめたことはありません。ビルドも QEMU も走らせていません。何も変えていません。

## 三つを分ける

プログラムは三種類あり、要るものが違います。

| | システムのプログラム | インストールされたアプリ | ポータブル |
|---|---|---|---|
| 入り方 | OS と一緒 | インストール形式 | 置くだけ |
| サービス | `declared[]` | 要る。形式で宣言し、入れるときに登録する。 | 持たない |
| メニュー、印、種類 | `system_programs[]` | 入れるときに登録する。 | 無い |
| 設定 | 設定のサービス | 自分で持つか、設定のサービス | 自分で持つ |
| 消し方 | OS の更新 | アンインストール | ファイルを消す |
| 今足りないもの | 無い | 欠陥 1、4、5〜9、11〜13 | 欠陥 1、16 |

## 今、後から入れる手順

コードから読める手順は、次のとおりです。

1. その OS の `common/abi.h` と同じ版で、静的な ELF を組みます。受けるのは `ET_EXEC` だけです（`kernel/src/sys/proc.c:184`）。
2. admin の利用者が、`C:\Programs\<アプリ>\` に置きます。`C:\Programs` に書けるのは admin 以上です（`kernel/src/fs/store.c:604`）。
3. ファイルの取り寄せは、端末の `fetch` か、OS の中の `tcc` です。ブラウザーには保存の道が見つかりません。`download` の語は、属性の宣言と sandbox の判定に当たるだけです（`user/libc/web/js_hyperlink.js:64`、`user/libc/web/frame.c:500`）。
4. 設定の窓の「アプリ」の頁で、名前、パス、種類を手で打ちます（`user/apps/settings.c:1176-1192`）。

結果は次の形になります。

- 印は `N_ICON_GENERIC` に決まります。
- 開始メニューにだけ出て、デスクトップには出ません。
- 名前は一つの文字列で、言語ごとの名前を持てません。
- 消すボタンは台帳から消すだけで、ファイルは残ります（`user/apps/programs.c:356-378`）。

## 欠陥と欠け

重いものから順に書きます。「誤り」は今の形が間違っているもの、「欠け」は無いものです。

### 土台：これが無いと配れない

#### 1. プログラムが syscall の番号を直接持つ

種類：誤り（形）。

- カーネルの ABI を保つ必要はありません。変えてよいです。問題は、その番号と構造体の形がプログラムの中に焼き込まれることです。
- 各プログラムは libc を静的に持ちます（`Makefile:328-329`、`user/libc/sys.c:36-43`）。
- 時計の構造体 `struct n_clock` も、アプリの中のコードが直接読みます（`user/libc/sys.c:76-100`）。
- そのため、OS が syscall を変えると、配ったプログラムは静かに壊れます。`common/abi.h:48` は、動かす OS の `abi.h` で組むものと書いています。
- Windows はカーネルの番号を保ちません。番号は版によって変わります。プログラムは OS と一緒に入る `kernel32.dll`、`ntdll.dll` などを呼び、番号はその中に閉じています。一つの `.exe` も、これらの DLL を読みます（一般の知識で、公式の文書と照らしていません）。
- Nocturne も同じ形にすれば、カーネルの ABI は自由に変えられます。保つのは、システムのライブラリーが外へ出す関数だけです。

#### 2. システムのライブラリーと、それを読む道が無い

種類：欠け。

- 受ける形式は `ET_EXEC` だけで、`PT_LOAD` だけを読みます。`PT_INTERP`、`PT_DYNAMIC`、再配置はありません（`kernel/src/sys/proc.c:34,184,210`）。
- `README_EN.md:612` も「No dynamic linking」と書いています。
- 手元の `build/programs` は 105 ファイルで 382 MiB です。`browser` は 88.1 MiB です。
- 今は、TLS や libc の修正がプログラムごとに組み直さないと届きません。システムのライブラリーに入れた部品は、OS の更新で届きます。

#### 3. プログラムの身元がパスのハッシュ

種類：誤り。私が `c51812ff` で入れた形です。設定の名前の範囲を動かすには足りましたが、インストールの土台にはなりません。

- 番号はパスの FNV-1a です（`kernel/src/fs/store.c:659-677`、`kernel/src/sys/authority.c:49-51`）。
- 移動や名前の変更で番号が変わり、設定が読めなくなります。
- 消した後に別のプログラムを同じパスへ置くと、前のプログラムの設定の値を読めます。これはコードからの推論です。
- `C:\Programs\<アプリ>` のフォルダーを変えるだけで、別のプログラムになります。
- スクリプトの番号は解釈系の番号です。`about.js` は `js` の番号で動きます（`user/apps/programs.c:45`、`user/libc/sys.c:433-446`）。同じ解釈系のスクリプトは、全部同じ設定の範囲を分けることになります。今は `.ts` のアプリが一つなので表に出ていません。
- 台帳の `id` は別の番号で、身元の番号とつながっていません（`user/apps/programs.c:48`）。

この番号は、OS の設定のサービスを使うプログラムだけの話です。第三者のプログラムは、自分の設定を自分で持てます。そのため、配るための土台ではありません。システムのプログラムと第三者のプログラムを、同じ形で考えません。

#### 4. プログラムの宣言（manifest）が無い

種類：欠け。

- `manifest` の語は実行系のコードに当たりません。
- 今の宣言は、三か所の手書きの表に分かれています。
  - `scripts/layout.py:32` の `APPS`
  - `user/apps/programs.c:20-46` の `system_programs[]`
  - `user/apps/services.c:60` の `declared[]`
- 付属のアプリを一つ足すにも、この表を手で揃えます。`layout.py` の注釈にも、`programs.c` が同じ場所を名指すと書いてあります。
- 付属のアプリ自身が「インストール」されていません。付属のアプリと第三者のプログラムの道が別です。

### インストールの本体

#### 5. 配る形式が無い

種類：欠け。

配る形は二つ要ります。どちらもありません。

| 形 | 例 | 何をするか | 要るもの |
|---|---|---|---|
| ポータブル | 一つの実行形式、ZIP | 置いて起こすだけです。OS には登録しません。設定も自分で持ちます。 | OS の側には何も要りません。 |
| インストール形式 | `.msi`、`.deb`、`.exe` | OS に入れます。台帳、印、種類、サービスへ登録し、消す道も持ちます。 | manifest、インストーラー、権限の確認、サービスの登録、アンインストール |

- 静的な ELF を一つ置いて起こす形は、今のカーネルの道で受けられます（コードの読みで、動かしていません）。止めているのは欠陥 1 と 16 だけです。
- ZIP を開く道具はありません。これはポータブルの条件でなく、OS の一般の機能です。`deflate.c` は HTTP の content coding 用として置かれています（`user/include/deflate.h:1-11`）。

#### 6. インストーラーが無い

種類：欠け。

- 窓も、サービスも、取消しもありません。
- 途中で失敗したときに戻す道がありません。一つの文書の差替えは原子的ですが、複数のファイルをまとめて入れる取引はありません。`n_entry_move` がフォルダーごとの移動に原子的かは確かめていません。
- ファイルを置く道（`C:\Programs`）と台帳へ載せる道（`N_PROGRAMS_REGISTER`）が別で、間で失敗すると片方だけが残ります。

#### 7. 権限を上げる道が無い

種類：誤り（設計の抜け）。

- 利用者の級は、その利用者が起こす全部のプログラムへ継がれます（`user/apps/session.c:155`、`kernel/src/sys/authority.c:35-52`）。
- admin が起こしたプログラムは、確認なしで `C:\Programs` に書け、台帳へ載せられます。他の利用者のフォルダーにも書けます（`kernel/src/fs/store.c:605`）。
- 一般の利用者が「admin の確認を受けて入れる」道がありません。`elevat`、`consent` の語は当たりません。
- 一般の利用者が自分の分だけ入れる道もありません。登録は admin 以上で、パスも `C:\Programs` に限られます（`user/apps/programs.c:324,484-485`）。
- 「普通の人がターミナルを開かずに使う」ためには、確認の窓と、admin の普段の権限の分け方を決める必要があります。

#### 8. アンインストールが無い

種類：欠け。

消す口は台帳から消すだけです（`user/apps/programs.c:356-378`）。消した後に残るものは次のとおりです。

| 残るもの | 根拠 |
|---|---|
| プログラムのファイル | `program_remove` は文書を消しません。 |
| 設定の値 | 設定の操作に削除がありません（`common/settings_abi.h:252-263`）。`value_remove` は保存の失敗の巻戻しだけです（`user/apps/settingsd.c:690`）。 |
| 各利用者の `AppData\<名前>` | 持ち主の記録がありません。 |

- `AppData\<名前>` は名前で決まるので、同じ名前の二つのプログラムが同じ場所を使います（`user/libc/sys.c:829`）。
- 媒体から消えた登録のプログラムは、台帳に残ります。起動の読込みで `on_medium` を見るのはシステムの表だけです（`user/apps/programs.c:262,291-293`）。

#### 9. 更新が無い

種類：欠け。

- アプリの更新の道はありません。版の番号を持つ場所もありません。
- OS の更新は、ホストの道具だけです。`hyperv.ps1 -Update` が VM を止めて書き込みます（`hyperv.ps1:9`、`scripts/layout.py:14-17`）。
- 動いている機械の中から OS を上げる道はありません。`user/apps` に `kernel.elf` を書く処理はありません。
- 起動の区画は、起動の記録の枠を上書きするだけです。大きさも変えません（`kernel/src/fs/bootrecord.c:3`）。
- 失敗したときに前の版へ戻す道もありません。
- 実機の更新の手順は見つかりません。媒体を作り直して入れ直す形になるはずですが、これは推測です。
- 付属のアプリと第三者のプログラムが同じ `C:\Programs` にあります。`fill` は `APPS` の名前のフォルダーを消してから詰めるので、同じ名前の第三者のフォルダーは消えます（`scripts/layout.py:76-106`）。

#### 10. 署名と出どころの確かめが無い

種類：欠け。

- 起こすときの確かめは ELF の形だけです（`kernel/src/sys/proc.c:184-187`）。
- ダウンロードの印（どこから来たか）もありません。ダウンロードの道が無いからです。

### OS との結び付き

#### 11. インストールされたアプリのサービスの道が無い

種類：欠け。ポータブルには関係がありません。

- 宣言の表 `declared[]` は固定で、組み直せる者しか足せません。
- `scope` は機械ごとと PCI の機能ごとの二つだけです。利用者ごとがありません（`user/apps/services.c:27-30`）。
- 宣言のサービスは常に利用者 0 の身元で動きます（`user/apps/services.c:361`）。
- `n_service_listen` の名前は、起動も再起動も依存も付きません。動いていなければ、要求は閉じられるだけです（`user/apps/services.c:756-758`）。
- 申し込まれた名前は `N_SERVICES_LIST` に出ません。設定の窓のサービスの頁にも、状況の窓のサービスとしても出ません（`user/apps/services.c:597-613`）。
- ログインのときに起こす一覧がありません。`session.c` に `autostart`、`startup` は当たりません。
- 第三者のドライバーの道もありません。`SCOPE_FUNCTION` の判定は C の関数です（`user/apps/services.c:51,66`）。

貼ってもらった Windows のタスク マネージャーの画面にある、AMD、Razer、Gaming Services などの常駐は、この道で動くものです。今の Nocturne には、これに当たる形がありません。

#### 12. 印が C のコードで、プログラムが自分の絵を持てない

種類：誤り（層の取り違え）。

- 印の種類は ABI の `enum n_icon` です（`common/services_abi.h:106-110`）。
- 絵はシェルの C の関数です（`user/apps/shell_art.h:208`）。
- 第三者のプログラムは `N_ICON_GENERIC` にしかなりません。
- 画像の読み手は libc にあるので、絵の文書を受ける材料はあります。

#### 13. 名前が言語ごとに持てない

種類：誤り。

- システムの表は言語ごとの名前を持ちます（`user/apps/programs.c:20-22`）。
- 登録の口は一つの文字列です（`user/include/nocturne_services.h:53`）。

#### 14. 開始メニューが並べるだけ

種類：欠け。

- 検索がありません。
- 分類がありません。よく使うものや、固定もありません。
- 印とメニューは機械で一つの旗で、利用者ごとに変えられません。利用者ごとなのは、種類の既定の選択だけです（`user/apps/programs.c:70-73`）。
- デスクトップの印は台帳の旗から出すだけで、動かせません。右クリックの処理は `shell.c` の一覧に当たりません。

#### 15. ブラウザーからダウンロードできない

種類：欠け。一般の OS で最初に要る入口です。

- `Downloads` のフォルダーは利用者ごとに作られます（`user/apps/accounts.c:175`）が、入れる道が見つかりません。`browser.c` の全部は読んでいません。

#### 16. ファイルの窓が、`C:\Programs` の外のプログラムを起こせない

種類：誤り。

- プログラムかどうかは、中身でなく今のフォルダーで決めています（`user/apps/files.c:25,56,84`）。
- ダウンロードのフォルダーの ELF は「File」になり、種類の既定へ回ります（`user/apps/files.c:210`）。
- プログラムかどうかは、フォルダーでなく中身で判定します。
- インストール形式のファイルは、開くとインストールの窓が出る形にします。

#### 17. 状況の窓がプログラムを知らない

種類：欠け。

- `struct n_procinfo` は名前と身元を持ちますが、プログラムの番号を持ちません（`common/abi.h:337-347`）。
- プログラムと、その部品やサービスをまとめて出せません。「アプリ」と「その裏の処理」の組が作れません。

### 安全

#### 18. 他の利用者のフォルダーのプログラムを起こせる

種類：欠陥。コードの読みで、動かして確かめていません。

- `proc_launch` は `store_document_open(path, N_DOCUMENT_READ, false, &doc)` で開きます（`kernel/src/sys/proc.c:177`）。
- 第三引数が偽だと、パスの権限を見ません（`kernel/src/fs/store.c:624,640`）。
- `sys_app_launch` の中にも、パスの権限の確かめは見つかりません（`kernel/src/sys/syscall.c:807-882`）。
- したがって bob は、`ls` できない `C:\Users\admin\x` を、パスを知っていれば起こせるはずです。
- 起こした子の級は親を超えません（`kernel/src/sys/authority.c:42`）。権限が上がる話ではありません。
- 前の仕事の境界の穴です。「読めないものは起こせない」が自然な形です。

#### 19. 同じ利用者のプログラムどうしの壁が無い

種類：決めること。

- 同じ利用者で同じセッションの USER 級のプログラムは、互いに届きます（`kernel/src/sys/authority.c:28-33`）。
- 一般のプログラムは、利用者のファイルと網の全部に届きます。能力で絞るのは特権の操作だけです。
- 宣言した権限で動かす形はありません。
- 従来のデスクトップの OS でもこの形は普通です（一般の知識で、調べ直していません）。ただ、配る形式を決めるときに manifest に権限の欄を残すかどうかは、後から足すと高くつきます。

#### 20. admin が既存のサービスの設定の持ち主になれる

種類：推測の欠陥。動かして確かめていません。

- admin 級のプログラムは、カーネルの鍵でない領域の鍵を再宣言して、持ち主になれるように読めます（`user/apps/settingsd.c:889-897`）。
- 第三者のプログラムが admin で動く今の形では、影響があります（欠陥 7 とつながります）。

### 作る人の側

#### 21. OS の外で組む道が公開の形になっていない

種類：欠け。

- `C:\Nocturne\SDK` と OS の中の `tcc` があります（`scripts/mksdk.sh`、`README.md:511-516`）。
- ホストで組む道は、このリポジトリのビルドの中にあります。Rust の道は `build/u/user/libc/crt0.asm.o` と `build/libc-objects.list` を読みます（`ports/rust/README.md`）。
- 取り出した SDK だけで、他の機械で組む手順は見つかりません。
- Go のアプリは `ports/go/apps/<名前>` に置いて、OS と一緒に組む形です。

## 依存の順

次の順に建てないと、前の仕事が無駄になります。

```
1・2 システムのライブラリーと、それを読む道
        ↓
4 manifest
        ↓
5 配る形式  →  6 インストーラー  →  7 権限の確認
        ↓
8 アンインストール  /  12・13 印と名前  /  11 サービス  /  16 ファイルの窓
        ↓
15 ダウンロード  →  10 署名  →  9 更新
        ↓
14 検索  /  17 状況の窓  /  21 SDK
```

- 18 は順に関係なく直せます。今の境界の穴です。
- 最初の到達点は二つです。
  - ポータブル：実行形式を一つ置いて、ファイルの窓から起こせます。
  - インストール形式：一つのファイルをダブルクリックで入れ、メニューに絵と名前で出て、設定の窓で跡を残さず消せます。

## 持ち主の案

実装はしていません。設計の前の叩き台です。

| 責務 | 持ち主の案 | 理由 |
|---|---|---|
| 何が入っているかの記録 | サービス `programs` | 既に台帳と保存を持ちます。別の登録簿を作りません。 |
| ファイルの配置と取引 | `programs` か、それが起こす system 級の部品 | `C:\Programs` への書込みを admin のプログラムから離せます。 |
| 確認の窓 | 窓のプログラム | UI とサービスを分けます。カーネルに持たせません。 |
| サービスの登録 | `services` の宣言の表を、固定と動的の二段に | 表の型は使えます。能力の上限を級で切ります。 |
| 設定の掃除 | サービス `settings` に削除の操作 | 値の持ち主です。 |
| 絵 | 台帳が絵の文書を指し、シェルが読む | ABI の enum から外します。 |

守る線も書いておきます。

- 「全部はファイルではない」に沿って、インストールは文書をフォルダーへ置くことでなく、型のある口で頼む操作にします。ファイルを編集して登録する形にしません。
- 他の OS のパッケージの形（依存の解決を持つ配布の倉庫など）を既定にしません。プログラムは自分の部品を自分のフォルダーに持つ形が、今の `C:\Programs\<アプリ>` に合っています。

## 決めてほしいこと

1. **システムのライブラリーの範囲。** カーネルの番号は保たず、ライブラリーを境界にする方向は決まりました。残る問いは、そこに何を入れるかです。最小は syscall の包みだけで、広くすれば libc、TLS、GUI も入ります。Go の移植は syscall を直接呼ぶので、直しが要ります。
2. **admin の普段の権限。** admin のプログラムを普段から admin で動かすか、確認の窓を通すまで USER 級で動かすかです。私の案は後者です。ただ、これは今の権限の仕事の形を変えます。
3. **利用者ごとのインストールを持つか。** 機械ごとだけなら、最初の到達点は簡単になります。
4. **インストール形式の動き方。** 配る形は、ユーザーの判断でポータブルとインストール形式の両方に決まりました。残る問いは、インストール形式が宣言だけのもの（`.msi`、`.deb` の型）か、プログラムを走らせるもの（`.exe` の型）か、両方かです。私の案は宣言だけから始めることです。確認の窓に入れる中身を全部出せ、跡を残さず消せるからです。
