# Nocturne の核の芯（立場 B：毎コマの道を核の中に）

## 1. 要旨

1. 核（ring 0 の一つの空間）は、隔離と期限の機構に加えて、毎コマ・毎事象の道にある自作の小さな service（NVMe と格納庫、xHCI と入力、NIC と流れの振り分け、合成の制御、音）を「核の区画」として持つ。アプリ・外から来たコード・nvrm・網の規約の解析は、主体の境界の外に置く。
2. 核の区画は守りの単位ではなく、失敗を封じ込める単位（門・台帳・区画ごとの記憶・装置ごとの IOMMU の領域・建て直し）。黙って記憶を壊す誤りは防げないので、核に入れるのは「毎事象の道にあり、小さく、自作」のものに限る。
3. CPU の時間は、期限という一つの順で配る。期限は画面の拍・入力・音・伝言から来て、群の予算で上限を持つ。残りは量の仕事（y-cruncher）へ長い区切りで渡す。核は横取りせず、短い区切りの間にある安全な点でだけ替わる。
4. 合成は GPU で行う。核が毎コマすることは、層の一覧を書き、提供者が前もって作った不透明な命令の塊を輪に置いて、戸（doorbell）を叩くことだけ（≤20 µs）。nvrm を呼ぶのは準備と回復の時だけ。
5. 根拠は Zen 4 の事実にある。PCID も PKS も無いので、主体をまたぐたびに TLB が消える。核に入るだけなら消えない。この費用を最初に実機で測り、小さければ格納庫などを外へ出す（A へ寄せる）。

## 2. 物差しの時間の予算

画面ごとに、予測した帰線 V より C だけ前の時刻 K に、核が合成を蹴る（kick）。アプリの present の締めは K で、拍の始まりは前の帰線。単位は µs。

| 段 | 280 Hz・1440p | 165 Hz・1440p | 600 Hz・1080p |
|---|---|---|---|
| 1 コマ T | 3571 | 6061 | 1667 |
| 入力：報告の間隔／核の道 | 125／≤10 | 125／≤10 | 125／≤10 |
| アプリ：拍の始まり→present | ≤2821 | ≤5311 | ≤1117 |
| 起こしの揺れの取り置き | 50 | 50 | 50 |
| 合成：核の kick | ≤20 | ≤20 | ≤20 |
| 合成：GPU の横取り | ≤200 | ≤200 | ≤200 |
| 合成：GPU の合成（全面の最悪） | ≤250 | ≤250 | ≤150 |
| フリップの締めまでの余白 | ≥230 | ≥230 | ≥130 |
| scanout（上から下） | 3571 | 6061 | 1667 |

ポインターは kick の時の位置で置く。だから報告から画面の上の行に出るまでは ≤125＋10＋T＋C で、280 Hz なら ≤4.4 ms。横取りと合成の値（1440p は約 44 MB の読み書き）は見込みで、段 0 の実測に置き換える。

同時の重さ（7600X の 12 thread、RTX 4070。真ん中の画面を 240 Hz と置く）：

| 群 | CPU | GPU・帯域 |
|---|---|---|
| 核の事象の仕事 | ≤0.5 thread、一件 ≤20 µs | — |
| 合成（三枚） | kick だけ | 高い優先の輪。最悪で 685 回/s×250 µs ≈ 17%、30 GB/s（504 の 6%） |
| ゲーム | 期限＋予算（例：8 thread×拍の 8 割） | 残り全部 |
| 動画・SNS | 拍・音・入力の時だけ期限 | 少し |
| y-cruncher | 予約の残りと、使われない予約 | 認めた固定の記憶。拍の群が動く間は MBE で帯域を絞る |

受入の線は二つ。フリップの記録で数えた落ちたコマが 0 であること。期限の起こしから走るまでが p99.99 で ≤20 µs であること。

## 3. 脅威の模型

| 何から | 何を守る | どこで止める |
|---|---|---|
| 悪意の・壊れたアプリ | 他の主体、ファイル、画面と入力、核 | 主体の境界、与えたフォルダーの範囲、UI と入力の権限（入力は前の窓だけ、画面の写しは許された主体だけ） |
| 外から来たコード | 上のものと、それを動かすアプリの残り | 主体の中の区画（権利を絞った下位のプロセス）。PKU は補い |
| 網からの悪い入力 | 核 | 核は見出しで振り分けるだけ。規約の解析は使う主体 |
| 壊れた核の区画 | 核と他の区画が動き続けること | 封じ込めと建て直し。黙った壊しは防げない |
| nvrm | 核と他の主体 | 主体の境界、claim、IOMMU、割り込みの再マップ |
| 装置の DMA・悪い USB 装置 | 記憶の全部 | IOMMU（核の装置も装置ごとの領域へ）、記述子の解析に上限 |
| 盗まれた機械 | 利用者のデータ、改ざん | 利用者の部分の暗号、起動と更新の署名 |
| 時間を奪う重さ | 滑らかさ | 期限と予算、L3・帯域の COS、I/O の予約 |

範囲の外：firmware・SMM・GSP、IOMMU が立つ前の DMA、SMT の隣の thread から漏れる横の路。

## 4. 空間と境界の配置

| 空間 | 何が動くか |
|---|---|
| 核（ring 0） | 強制の核（時刻と期限、CPU の配り、記憶、物と権限、やり取り、割り込み、IOMMU、PCI の持ち主）と、核の区画（NVMe＋格納庫、xHCI＋HID＋入力の行き先、NIC＋流れの振り分け、合成の制御、音の混ぜ、ACPI（firmware の言葉なので元から TCB）、VM の装置（`vm.h` の後ろ）） |
| system の主体 | nvrm（RM・NVKMS・UVM）、shell（taskbar・menu・窓の枠・通知）、網の世話役（ARP・DHCP・ICMP）、設定 |
| アプリの主体 | ブラウザー（取得・媒体・保存・Worker）、ゲーム、動画、y-cruncher。TCP・UDP・DNS は使う主体の library |
| 主体の中の区画 | 頁の JS・Wasm、移植物の危ない部分（既定は下位のプロセス） |

主体の境界は、主体ごとの空間と handle の表（capability）で引く。GPU の文脈は主体ごとの RM client で、GPU の MMU が分ける。網の規約を外へ出したのは、出発点からの変更。悪い入力の解析は、同じ相手の TLS・HTTP をすでに解いている主体に置くのが筋で、一つのパケットの道で主体をまたぐ回数も増えない。

## 5. 芯の部品

### 5.1 CPU の時間の配り
画面の期限・入力・ゲーム・動画・SNS と、全コアの y-cruncher を同時に満たすためにある。
- 形：CPU ごとに、走れるもの（thread と事象の続き）を期限の早い順に並べる。期限は起こした物から来る。窓の画面の K、入力の時刻＋目標、音の装置の残り、伝言の送り手の期限、そして錠の持ち主には待つ者の期限。期限は群の予算を使い、使い切れば補充まで期限を失う。量の仕事は残りを重みで分け、長い区切り（例 8 ms）で替える。使われない予約はすぐ量の仕事へ回す。
- 出所：周期の合わない三つの締めは、固定の優先では利用率 78%（数が多いと 69%）までしか守れない。締めの早い順なら一つの CPU で 100% まで守れる。予算は、締めを名乗るだけで先に走れる穴をふさぐ唯一の上限。期限を伝えるのは、一コマの仕事が多くのプロセスに分かれるため。似ているもの：実時間の文献の「締めの早い順と予算」、Darwin の緊急度の伝搬。違い：級が無く、期限は時刻そのもの。
- 数字と 1024：選ぶのは heap の根で、入れ替えは ≤1 µs、周期の拍は無い。置き場所は、LLC ごとの「量の仕事を走らせている CPU」の bit 列で選ぶ。予算は node の溜めから切り取る。眠る CPU は MWAIT で起こし語を見張り、起こす側は語へ書き込むだけ（IPI は要らない）。L3 と帯域（COS 16、MBE・SMBE）を群に結ぶ。

### 5.2 時刻と期限
一つの時間の基、CPU ごとの期限の列、起こしの源のためにある。
- 形：基は TSC。帰線と音の装置は TSC への一次の写像として持ち、まとめて届く実測で直す（誤差 ≤50 µs）。各 CPU の LAPIC one-shot に、その CPU の一番早い期限をじかに書く。起こしの装置を抽象する層は作らない（VM は `vm.h` の後ろ）。
- 出所：TSC は不変。TSC-deadline は無い（PPR 56713 で CPUID 1 ECX の bit 24 は Reserved、LVT Timer の Mode は 1 bit だけ）。LAPIC timer は 2×CLKIN（200 MHz）で数え、C 状態でも止まらない（ARAT）。
- 数字と 1024：刻みは 5〜40 ns、一度に最長 21.4 s。近い起こしは許しの幅でまとめる。列は CPU ごとに持つ。ソケットをまたぐ TSC の揃いは起動時に測る。

### 5.3 割り込みと装置の事象
装置の事象を、それを待つ仕事へ最短で届けるためにある。
- 形：MSI-X は、装置の待ち行列ごとに、装置の node・LLC の CPU へ向ける。割り込みの中では、区画の事象の関数が 5 µs まで働く（完了を読み、輪へ書き、待つ thread を期限つきで起こす）。残りは事象の続きとして、待つ仕事の期限で列に入る。thread へ回さず、優先の段も作らない。
- 出所：NVMe・xHCI・NIC は待ち行列ごとに MSI-X を持てる。xHCI は interrupter ごとに IMOD（250 ns 単位）を持つので、HID だけの interrupter を作れば 8000 Hz を間引かずに受けられる。似ているもの：割り込みの後の続き。違い：ここでは続きも期限の列の一項目。
- 数字：8000 Hz×3 µs＝1 CPU の 2.4%。NVMe 150 万 IOPS を 16 件ずつまとめて約 0.5 CPU。

### 5.4 待ちと同期
待つ thread を眠らせ、期限の逆転を起こさないためにある。
- 形：核は横取りしない。核の中の thread が替わるのは安全な点（利用者へ戻る時・眠る時・長い仕事の区切り）だけ。区切りは ≤20 µs を目標にする。安全な点で前の点からの時間を測り、50 µs を越えたら場所を記録へ出す。錠は物ごとの MCS の spinlock（安全な点をまたいで持たない）と、眠る錠。利用者の錠の語には持ち主の thread を書く約束にし、待つ者の期限を持ち主へ渡す。回収に使うのは、参照の数と slot の使用の数と、相手の決まった待ちだけ。
- 出所：横取りを禁じる入れ子を数えずに遅れを抑える道は、区切りを短く保つことしかない。数えないので、CPU ごとの状態も spinlock も、作りそのもので安全になる。似ているもの：古い非横取りの核。
- 数字：起こしは量の仕事を走らせている CPU を選ぶので ≤20 µs、最悪で 50 µs。

### 5.5 記憶
物理の頁・空間・大きな頁・固定した記憶・NUMA と CXL のためにある。
- 形：node ごとの buddy の上に「2 MiB の持ち主」の層を置く。2 MiB の塊を一人の持ち主（群か区画）に配り、4 KiB はその中で割る。持ち主が終われば塊は丸ごと戻る。頁は動かさない。固定した記憶は群の記憶の予約として認める。直接の I/O は、固定している間だけ NVMe の IOMMU の領域へ写す。撃ち落としは、今その空間を走っている CPU へだけ送る。
- 出所：何日も動くと、散らばった 4 KiB が 2 MiB を壊す。持ち主で分ければ、頁を動かさずに保てる。PCID が無いので、CR3 を替えた CPU にはその空間の訳が残らない。INVLPGB は 7600X に無い。
- 数字と 1024：32 GB は 16384 塊。24 GB の固定は 2 MiB の頁で 12288 枚になり、TLB が届く範囲は 512 倍。撃ち落とし一つは約 1〜2 µs。塊の表は node ごとに持つ。CXL は記憶だけの node として扱い、拍の群には配らない（SMBE で帯域を絞れる）。

### 5.6 物と権限
handle の表は主体ごとに持ち、各 handle は権利の bit を持つ capability。表は二段の目次で伸ばし、slot は動かさない。引く時は、slot の使用の数を一つ上げて世代を確かめるだけ（錠なし、≤30 ns）。閉じる者は、待っている者を N_ERR_CLOSED で起こし、その slot の使用が 0 になるのを待つ。静かな点で回収する形を使わずに、錠なしの引きを安全にするいちばん小さな形。ファイルは、主体に与えたフォルダーの範囲の中で名前を解く。

### 5.7 やり取り
伝言のチャンネル（今の ABI）、共有の記憶、輪と知らせの語を使う。受け手は眠る前に語へ「眠る」と書き、送り手は書いた後に語を見て、眠っている時だけ起こす。伝言は送り手の期限を運ぶ。主体をまたぐのは一コマに一回まで。見込みは syscall 0.1〜0.3 µs、主体をまたぐ往復 2〜5 µs（段 0 で測る）。

### 5.8 プロセスと thread と寿命
アプリの番号と thread の番号は別の数にし、どちらも使い回さない。持ち主ごとの台帳に、持っている資源を全部載せる。終わりは台帳をたどるだけで、全体を走査しない。止めは、各 thread の次の安全な点で効かせる。

### 5.9 失敗と再起動
区画が落ちても、核と他の区画とアプリが動き続けるためにある。
- 形：区画は、読むだけのコード＋自分の arena（自分の 2 MiB の塊、間に守りの隙）＋台帳＋装置ごとの IOMMU の領域＋門でできている。門は戻り点（レジスターと shadow stack の位置）を残し、引数を写してから確かめる。核の呼び出しは、錠を放してから区画へ戻る。
- 見つけ方：区画の中の例外（守りの頁・#PF・#CP・ASSERT）、読むだけで写してある核の表（頁表・IDT・handle の表・台帳）への書き込み、予算を越えた要求。
- 後始末の順：落ちた thread を戻り点へ巻き戻し「建て直し中」を返す → 区画の中にいる他の thread も門の出口で同じく → 装置の BME を切り、IOMMU を全部止めにして FLR → arena を捨てる（他の区画が指している分は数が 0 になるまで寝かせる）→ 台帳の資源を外す → 初めの写しから新しい世代を作る。handle は世代を持つ。nvrm は主体として起こし直し、その間は CPU の提供者で合成する。
- 出所：Zen 4 の ring 0 には安い区切りが無い。PKS が無い。PKU は利用者の頁にしか効かず、WRPKRU は ring 3 から打てる。LMSLE も無い。区画ごとの頁表は、PCID が無いので替えるたびに TLB を消す。前向きの CFI は kCFI（IBT は無い）、後ろ向きは supervisor shadow stack で補う。
- 数字（見込み）：門は約 20 ns。建て直しは、合成が 1 コマ＋数十 ms、格納庫が数 ms、NVMe が数百 ms（CAP.TO が上限）、入力が秒まで。

### 5.10 合成の制御と GPU の継ぎ目
三枚の画面を、それぞれの時刻で毎コマ GPU で合成するためにある。
- 形：核は窓の物（面・位置・重なり・present の列・描き終わりの semaphore の値）と、head ごとの場面と拍（V と K）を持つ。K の割り込み（head ごとに別の CPU）で、次のことをする。描き終わった絵だけを選ぶ（semaphore を一回読む。間に合わない絵は前の絵のまま）。層の一覧を書く。提供者が前もって作った不透明な命令の塊を GPU の輪に置いて戸を叩く。フリップも、提供者の塊（合成の完了を待ってから面を替える）を表示の輪へ置く。全画面の窓はフリップだけで済ませる。継ぎ目の契約は「不透明な塊・輪・戸・完了の語」で、実装は nvrm（準備だけ）、CPU の提供者（GOP・VM）、RDP の三つ。
- 出所：CPU で合成すると書くだけで 9〜11 GB/s 要る。nvrm は ring 3 なので、毎コマ nvrm を起こさない道は二つしかない。GPU がすでに持つ輪と戸（利用者の提出。NVK がそう使っている）と、表示の channel の push buffer。
- 未確認：NVKMS と RM がそれらを核へ渡せるか、フリップが semaphore を待てるか。駄目なら、塊を置くのは nvrm の期限つき thread に任せる。

### 5.11 記録と診断
型つきの記録を CPU ごとの錠なしの輪へ書き、文字にするのは読み手（serial、System.log、F12、コマの表）に任せる。コマの記録で、落ちたコマとどの段が遅れたかを名指す。panic は別の道を通す。形の出所：競り合わずに書くには書き手一人の輪が、機械で辿るには型が要る。似ているもの：NT の型つきの事象。1 件 ≤50 ns。

### 5.12 電源（S3）と起動
- 起動：UEFI → CPU・topology・塊・時刻・IOMMU → 区画を依存の表に沿って並べて初める → まず GOP の面に CPU で合成し、nvrm が輪を出したら GPU へ移る。
- S3：予約を止め、区画の眠りの門を依存の逆の順に通し、nvrm には眠りの約束を求める（今の ABI は claim がある間は眠らないので、変える）。
- 起きる時：全 CPU を一斉に起こし、TSC を揃え、期限の列から LAPIC を掛け直し、IOMMU → IOAPIC → PCI → 区画 → 輪の順に戻す。

## 6. 今のコードへの影響

| 場所 | 扱い |
|---|---|
| `arch/` | 残る：GDT・IDT・SMP の起動・FPU・topology・PAT・S3 の wake・`spin.h`。作り直す：`irq.c`、`idle.c`。消す：`preempt.h`、`lapic_timer.c`（TSC-deadline の枝は Zen 4 では通らない） |
| `sys/` | 作り直す：sched・wait・thread・process・object・channel・events・clock・alarm・log。消す：epoch。呼び方を変える：keep・watch・panic・prof。`syscall.c` は持ち主ごとの門へ割る（番号は保つ） |
| `mm/` | 呼び方を変える：pmm（2 MiB の持ち主）、heap（区画の arena）。作り直す：vmm の撃ち落とし |
| `dev/` | 残る。各ドライバーを区画にする。iommu は核の装置も領域へ入れる。`pciuser.c` に表示の輪の口を足す |
| `fs/`・`common/store/` | 残る。一つの rwmutex の門を CPU ごとの数に割る。直接の I/O と I/O の予約を足す |
| `net/` | `rtl8125.c` と振り分けは残る。TCP・UDP・DNS は libc へ移す |
| `gui/` | `wm.c` は作り直して合成の制御だけにする（`MAX_WIN` も消える）。`desktop.c` は shell へ。`screenmode.c` は残る |
| `vm/` | 残る（`vm.h` の後ろ）。Hyper-V の画面と RDP は表示の提供者になる |
| ABI・`ports/nvidia` | 番号は保つ。足すもの：直接の I/O、予約、描き終わりの値つきの present、raw の入力の輪、流れの handle、眠りの約束。`display.c` に輪の提供を足す |

## 7. 作る順

- 段 0（実機で測る）：今の核のまま、測りのアプリが表を画面に出し、写真で読む。測るものは次の八つ。
  - (a) syscall
  - (b) 主体をまたぐ往復（輪・起こし・CR3・TLB の戻り）
  - (c) IPI と起こし語
  - (d) LAPIC one-shot の遅れ（無負荷／全 thread の AVX-512／C1・CC6）
  - (e) 8000 Hz の割り込み
  - (f) NVMe（IOMMU の素通しと領域）
  - (g) GPU の合成の提出から完了までと、重い描画の下での横取り
  - (h) MBE・CAT の効き

  決め手：(b) が負荷の下で p99.99 ≤5 µs なら、格納庫と入力を外へ出す案を比べ直す。(g) が 200 µs を越えたら C を広げる。
- 段 1 時刻と CPU の配り：280・240・165 Hz の期限と全 thread の AVX-512 を 1 時間走らせ、落ちた期限が 0 であること。
- 段 2 記憶：断片化を速めた後でも、24 GB を 2 MiB の頁で固定できること。
- 段 3 物・やり取り・プロセス：今のユーザーランドが ABI のまま動き、実サイトとの照合で退行が無いこと。
- 段 4 区画の枠と、NVMe＋格納庫・xHCI＋入力・NIC：故障を入れた時の建て直しの時間と、失うのが最後の確定の後の分だけであること。NVMe が飽和した中での、ブラウザーの小さな読みの遅れ。
- 段 5 合成：まず CPU の提供者、次に nvrm の輪。実機の三枚の画面でゲーム＋動画＋SNS＋y-cruncher を 1 時間動かし、落ちたコマが 0 であること。
- 段 6 S3、記録の読み手、Hyper-V 第 2 世代と拡張セッション（VM で通ったことは実機の証拠にしない）。

## 8. 弱い所と未確認

1. 核の区画は守りではない。区画の記憶を壊す誤りは、核と他の区画を黙って壊しうる。打てる手は、入れる物を絞り、kCFI・shadow stack・読むだけの核の表で確率を下げることだけ。
2. 悪い入力の解析が核に残る。USB の記述子、網の見出し、C: の構造（盗まれた機械で書き換えられうる）。
3. nvrm の輪はまだ机の上の案。駄目なら、毎コマ nvrm を一回起こす。
4. 核のコードが多いので、区切りを忘れた輪が一つあるだけで入力の遅れが壊れる。記録で見つけられるが、防げない。
5. 建て直しは、落ちる前に確定された壊れた中身までは直さない。
6. 固定の記憶は時間で分けられない。y-cruncher が先に 24 GB を固定すれば、後から来たゲームは入れない。
7. GPU の横取りの遅れが分かっておらず、これが C を決める。
8. 1024 CPU と EPYC（INVLPGB、ソケット間の TSC、CXL）は机の上だけ。
9. B の得は主に遅れと揺れで、量だけなら A もまとめれば近づく。段 0 の (b) が小さければ、格納庫と入力を主体へ出す（A へ寄せる理由になる）。時刻・CPU の配り・合成の制御は、どちらの立場でも核に残る。

## 9. 持ち主が決めること

| 決めること | 選択肢 | 推し |
|---|---|---|
| 核に入れる線 | ①毎事象の道にある自作の service ②格納庫も外 ③網の規約も核 | ①。段 0 の (b) で見直す |
| 網の規約 | 使う主体の library／核の区画 | library |
| 核の横取り | 安全な点だけ／どこでも（入れ子の数が要る） | 安全な点だけ |
| nvrm の毎コマ | 核が塊を置く輪／nvrm の thread を毎コマ起こす | 輪。駄目なら thread |
| shell（taskbar・menu・窓の枠） | 核から出す／残す | 出す（固まったアプリでも閉じる釦が動く） |
| ファイルの権限 | 与えたフォルダーの範囲／今のまま全部 | 範囲 |
| 盗まれた機械と起動 | 暗号の範囲と鍵、署名の鍵の持ち主 | 利用者のフォルダーを暗号にし、システムは持ち主の鍵で署名 |
| 建て直しの約束 | 失敗を返す／繰り返せる要求はやり直す | 読みはやり直し、書きは失敗を返す |
