## 2 建てた口、契約、上限
- **`dev/refclock.h`・`.c`（新規）**：`struct refclock`（名、bit 幅、読みの揺れ、Hz の分子と分母、`read(ta, tb)` は数を二つの TSC の読みの間で取る、`resume`）。`refclock_get(i)` は HPET、次に ACPI PM timer を返す。HPET は IA-PC HPET 1.0a に、PM timer は FADT の X_PM_TMR_BLK か PM_TMR_BLK に（24 bit か 32 bit）従う。`rtc_read(&unix_s)` は MC146818 を、UIP が二度とも 0 で秒が同じときだけ読む。FADT の CENTURY（ACPI 6.5 表 4.10）と IAPC_BOOT_ARCH の bit 5（§5.2.9.3）を見る。
- **速さ**：CPUID 15h、次に登録された値（`clock_register_tsc_hz`、Hyper-V の周波数の MSR）、次に参照の時計で測る。この順は §4.3 どおり。
  - 起動の測りは上限の各部が 2^-14 未満になるまで続く。最初の速さは参照に対して 2^-13（122 ppm）以内。
  - その後は alarm が倍になる窓で測り続ける。窓の上限は長さに反比例し、倍の窓で半分になる。新しい値を採るのは、二つの上限の中で今の値と合い、しかも上限が小さいときだけ。合わなければ速さが動いたと見て、最後の窓の値を採り、窓をそこから数え直す。
  - 傾きだけを変え、時計は跳ばず戻らない。速さを変えるたび、上限・窓・累積の誤差（ns）を一行に出し、`alarm_clock_changed()` で全 CPU の起こしを立て直す。
  - HPET そのものの精度は ±500 ppm（1.0a 2.4.1）。PM timer は ACPI が精度を言わない。
  - 幅の狭い数え手は一周の 1/4 ごとに読む（PM の 24 bit なら約 1.17 秒ごと）。
- **時計の data**：`struct clock_data` を自前の頁に置く。頁の数は CPU の数から決め、`clock_data_pages()` で出す。seqlock で、変換・三つの時計・CPU ごとの offset を同じ所に持つ。核と利用者は同じ offset の表を RDTSCP の TSC_AUX で引く。`clock_tsc_hz` も seqlock の中で読む。
- **`clock_now_ns()`（D の要件）**：錠を取らない。時計の前は 0 を返す。NMI の中からも読める。
  - 書く CPU の上の NMI は、書く前の値と自分の書く前の offset を読む。
  - ほかの CPU の読み手は、書きが続く間（割り込みを閉じた数個の書き。一番長くても CPU ごとの offset の書き）だけ待つ。
  - `clock_stop()` を呼んだ後は、どの読み手も待たずに書く前の値を読む。panic で書く途中の CPU が止められても読み手が待ち続けないための口。
- **三つの時計**：
  - 単調の時計は S3 で止まる。
  - 起動からの時計は、単調の時計に data の `asleep_ns` を足したもの。
  - 壁時計は RTC の秒から始め、単調の時計の上を走る。RTC の次の秒の縁を alarm の二分で探し、分かった分だけ前へ進める。探りの幅は drift の 4 倍と読みの幅を足したところで止める。drift の初めの見込みは 1 秒あたり 2^-10 で、食い違いが出るたびに倍にする。見つけた幅は行に出す。
  - `clock_set_wall`、`clock_adjust_wall(offset_ns, slew_ppm)`：slew の間、速さは slew_ppm 以内に収まる。ppm が 0 か 10^6 以上なら一度に進める。
- **復帰**：単調の時計は止まった所から続ける。TSC が数え続けていて、その数が RTC の幅に収まるなら、その時間を足す。寝ていた時間は RTC の前後の読みが示す下限を起動からの時計と壁時計に足し、縁が見つかればその分を足す。`clock_resume` は寝ていた秒を返す。
- **CPU の比べ**：`clock_cpu_compare`・`clock_cpus_compare` は全 CPU が一斉に下限で比べる。残る差は cache line が渡る時間より小さい。offset は読みを上げる向きにしか変えない。
- **起こしの装置（`lapic_timer.h`）**：
  - `lapic_wake_init`・`lapic_wake_at`：TSC-deadline があれば `clock_tsc_at` で直接 arm し、偏りを持たない。無ければ one-shot で、CPU ごとの「TSC あたりの数」を下限で較正する。最初の幅は約 2^-8 で、arm のたびに測り上げる。だから割り込みは時刻より前か時刻ちょうどに来て、後には来ない。数の段は 8（PPR 55898 2.1.12）。
  - `lapic_timer_always_running()` は CPUID 06h EAX[2]（ARAT）を返す。
- **alarm**：
  - `alarm_set_range(a, earliest, latest)` を足した。`alarm_set` はその両端を同じにした inline。
  - 同じ alarm が二つの CPU で同時に立っても、`armed_on` の取り合いで一つの heap に入る。
  - 火は割り込みの中で走り、二つの CPU で同時には走らない。早く来た割り込みは heap が立て直す（`early ≤ now` のときだけ火を付ける）。
  - `vector_register(VEC_TIMER, …)` は残した。
- **`clock_spin`**：仕様が求める数 µs の待ちだけに使うと見出しに書いた。

## 3 §4.3 との違いと理由
- ARAT は `lapic_timer.c` で自分で読んでいる。本来は A1 の `cpu.c` の `cpu_features` の持ち物で、そちらに欄ができたら移す。
- 言われた値（CPUID 15h、登録された値）は測り直さない（`rate_bound` は 0）。測り続けるのは測った速さだけ。
- LAPIC の比は時計でなく TSC に対して測る。時計の速さが変わっても測り直しは要らない。
- 寝る前の RTC の読みは `clock_suspend` の中で行う。前の側に ±1 秒の幅が残り、後で縁を見つけて狭める。装置を止める前に読めればもっと狭まるが、それには `pm.c` に足す所が要り、持ち物の外。
- 起動の縁探しで、壁時計が一度だけ前へ跳ぶ（1.5 秒未満）。
- `clock_adjust_wall` にはまだ呼ぶ側が無い。起動からの時計を核の中で読む関数も、呼ぶ側が無いので作っていない。
- data の頁を利用者の空間へ写すのは波 3。
- 起こしの割り込みとその alarm の取り直しが重なったとき、火が arm した CPU とは別の CPU で走ることがある。同時に二か所で走らないことは守る。
- 設計で決めた比で、仕様から来ていないもの：`BOOT_SHIFT` 14、`CALIBRATE_SHIFT` 10、窓の余裕 1/64、`EDGE_DRIFT` 2^-10、縁探しの上端 +1.5 秒と取り直し +0.5 秒。RTC の水晶の許容差は手元の資料に無い。
- `rtc_now` は起動・寝る前・復帰のときに、時計で上限 1 秒まで待つ。ふつうは一回の更新ぶん、約 2 ms。
- `clock_stop` は §4.3 には無い。D の要件のために足した。
