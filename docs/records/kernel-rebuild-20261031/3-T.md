### 仕事
3-design.md §4.3〜§4.5 の契約どおりに建て直す。要点：

1. **時計は三つ。**
   - `N_CLOCK_MONOTONIC`：起きている間だけ進み、起動で 0。
   - `N_CLOCK_BOOT`：眠りも数える。
   - `N_CLOCK_WALL`：UTC の Unix 時刻の ns。閏秒は数えない。
   - 核の `clock_now_ns`・`clock_boot_ns`・`clock_wall_ns` と同じ物。
2. **時計の頁をアプリへ。**
   - `struct clock_data` の形を ABI にする。
     - 定義は `common/` の一つの見出しへ移し、先頭に版の欄を置く。核と libc が同じ定義を組む。
     - 読みの式（seq、TSC、CPU ごとの差、速さ）の持ち主はこの見出しの注釈。
   - 核は各アプリの空間へ、読むだけの範囲として写す（3-V の範囲の種類）。番地は `struct n_start` の欄で渡す。
   - CPU の番号は RDTSCP の TSC_AUX。
3. **libc は `n_clock_now(clock)`（ns）一つ。**
   - 消す：`uptime_ms`・`uptime_us`・`n_clock_uptime_ms`・`n_clock_wall`・`clock_info`・`user_clock_us`。
   - 使い手を `n_clock_now` の ns に直す。user・tests・ports で約 980 か所あり、書き換えは機械的。
   - ISO C の `timespec_get`（`TIME_UTC`・C23 の `TIME_MONOTONIC`）・`time`・`thrd_sleep` もこの関数で。
   - 消す syscall：`SYS_UPTIME`・`SYS_TIME`・`SYS_CLOCK_INFO`。あわせて `struct n_clockinfo`・`N_CLOCK_USER_TSC`、`n_sysinfo` の `uptime_ms` も消す。番号は空けたまま。
4. **移植。**
   - 頁を読むもの：Go の runtime（`nanotime1`・`walltime`）、Rust の std（`Instant`・`SystemTime`）、`ports/nvidia/os.c`（二つ目の時計を消す）。
   - 式の写しは、`common/` の見出しの注釈に結ぶ。
5. **期限は絶対の `N_CLOCK_MONOTONIC` の ns。**
   - 対象：`SYS_WIN_RECEIVE`・`SYS_EVENTS_WAIT`・`SYS_APP_RESULT`・`SYS_PAGER_TAKE`・`SYS_PCI_INTERRUPT_TAKE`・`SYS_PCI_ACPI_NOTIFY_TAKE`・`SYS_PCI_SCREEN_STATE`・`SYS_WAIT_ADDRESS`・`SYS_WAIT_ADDRESS64`・`SYS_UDP_RECV`・`SYS_TCP_RECV`・`SYS_TCP_ACCEPT`・`SYS_TCP_CONNECT`・`SYS_NET_PING`。`SYS_NET_PING` は往復の時間も ns で返す。
   - 値の意味：0 は待たない、`N_NEVER`（`UINT64_MAX`）は限りなし。期限が来たら `N_ERR_TIMEOUT`。
   - `SYS_TCP_SEND_UNTIL` は `SYS_TCP_SEND` 一つにまとめる。
   - 入口で期限を換えない。`syscall_deadline`・`address_deadline` は消す。相対を足すのは libc で一度。
6. **時計を選ぶのは眠りと timer だけ。**
   - `SYS_SLEEP_UNTIL(clock, deadline)`。
   - `SYS_EVENTS_TIMER(queue, clock, first, period, token)`。
   - 核の側：起きている時計と壁の時計の期限の鎖（今は大域の `boot_lock` の `boot_sleeps`）を、CPU ごとに割る。時計が動いた時（眠りの後、壁の時計の跳び、`clock_adjust_wall`）は、各 CPU が自分の鎖を引き直す。待ちの入りと出に大域の錠を置かない。
7. **事象の時刻。**
   - `struct gui_event` の `time`（単調の ns）：
     - 入力は割り込みの時。今の xHCI・HID の道で取れる時を付け、wm を通して窓の行列まで運ぶ。VM の合成装置は vm/ の受け取りの時。
     - `EV_FRAME` は表示の時と表示の番号。
     - ブラウザーの `Event.timeStamp` と `requestAnimationFrame` の時刻はこの値から。
   - `struct n_event`：`reserved` に `time` と timer の回数を持たせる。
   - `struct n_audio_status`：`played_time` を足す。
   - `SYS_PCI_SCREEN_VBLANK` の `timestamp_ns` は単調の時計（driver は時計の頁を読む）。
   - `n_procinfo`：`cpu_ms`・`start_ms` を `cpu_ns`・`start` に。
   - `n_entry` は変えない。

### 決まり
- 持ち主の単位で消してから建てる。
  - 古い道を残して新しい道を足さない。古い時計の名を新しい名へ渡すだけの包みを残さない。
  - shim（何もしない関数、渡すだけの包み、偽の環境）を作らない。名前だけの口を作らない。
- 決め打ちの上限を置かない。待ちは割り込みか事象で起こされる形にし、決まった間隔の見回りや回数の spin を作らない。
- 核は横取りされる。利用者の記憶は写しだけで触る（SMAP）。時計の頁は核だけが書く。
- 速くするためにイベントの順序や時刻の意味を壊さない（AGENTS.md「性能」）。
- 自分の持つファイルの外は、上の仕事が名を挙げた所だけ、口を変えるための最小の行だけ。
- コードの注記は周りに合わせて英語。今あるコードの書き方（名前、注記の濃さ）に合わせる。
- 編集は Edit・Write で。シェルや Python でファイルを書き換えない（この Windows の Python は LF を CRLF に変える）。約 980 か所の書き換えも Edit で。数が多ければサブエージェントに分けてよいが、差分は自分で読む。シェルは Bash（Git Bash）。探すのは `rg`。
- 組んで確かめる：
  - 作業木の根で `python -X utf8 scripts/build.py -j 8 kernel` と `user`（出力は本体の `build/wt/<作業木の名>/`）。
  - Go・Rust の移植は、道具があれば組む。
  - 警告を増やさない。
  - QEMU は起こさない（本体が取り込んだ後に起動して確かめる）。媒体（img）は作らない。
