### 仕事
1. **壁の時計は UTC**（§3.1）。カーネルの中も ABI も UTC だけを渡す。
2. **時間帯の持ち主はカーネル**（§3.2）。
   - tzdb の元：`D:\Programes\cloned repos\go\lib\time\zoneinfo.zip`（tzdb 2026c を zic で組んだ TZif、RFC 8536）を `third_party/tzdb/` に写し、版と出どころを README に書く（ダウンロードはしない）。
   - ホストの道具（`scripts/` の Python）が zip の TZif から一つの二進の表を組み、C: の `Nocturne\System\` に置く（`scripts/layout.py` と Makefile の生成の規則。生成物は生成元から。空の build/ から組んでも通ること）。各 zone は移り目の列（UTC の時刻、ずれの秒、夏時間の印、略号）と、表の最後の年の後の規則（TZif の末尾の文字列を組む時に読んで表の形に直す）。
   - 表の読み手は `common/` の一つの部品（`common/store` と同じく、カーネルと libc が組む）。時刻 t と zone から、ずれ・略号・夏時間・次の移り目を返す。
   - 設定は IANA の zone の名。keep の部品「Time」（`sys/keep.h`）で `AppData\Nocturne\Time.conf` に書き、init より前に読み戻す。持ち主はカーネルの新しい部品（責務の名で）。
   - ABI：今の zone の名を読む、zone を変える（システムの設定）、zone が変わったことを知る見張り（今ある見張りの部品 `sys/watch`）。地方時の計算は ABI に置かず、各プロセスが表と `common/` の読み手で行う（syscall なしで `localtime` が引ける）。`docs/nocturne-native-abi.md` を同じコミットで直す。
   - libc：`localtime`・`mktime`・`strftime`（`%Z`・`%z`）を時間帯で（`user/libc/time.c` の「localtime == gmtime」を消す）。zone の変化を見張りで知って読み直す。
   - QuickJS の `getTimezoneOffset`（`third_party/quickjs/quickjs.c` の `CONFIG_NOCTURNE` の道）を libc の時間帯から。ブラウザーの Intl の既定の時間帯と formatjs の詰めた zone のデータの置き換えは次の段（T1b）で、ここでは触れない。
   - タスクバーの時計（`gui/wm.c` の `time_to_parts(clock_wall_seconds())`）は地方時で描き、zone が変わった瞬間に描き直す。
   - 設定の窓：設定アプリ（`user/apps/settings.ts`）に時間帯を選ぶ頁（地域で絞れる一覧、今の地方時の見本）と、RTC の意味（次の 3）を選ぶ項目。変えた瞬間に効く。
3. **RTC の意味は設定**（§3.3）。UTC か地方時か。既定は地方時。Time の部品に一緒に持つ。カーネルが RTC を読むとき、地方時なら設定の時間帯の表で UTC に直す。夏時間の移り目の前後の重なる一時間は、RTC だけでは決まらない区間として下限と上限の幅に入れる。RTC を読み書きする持ち主は `dev/refclock.c`。起動の早い時（C: を mount して Time を読み戻す前）の壁の時計の扱いを決め、報告に書く（その間に壁の時計を読む所、例えば格納庫の書き込みの時刻を探して並べる）。
4. **壁の基準の口を区間に**（§3.4）。`clock_wall_proof` を「`by` の時に時刻は `[at_least, at_most]` の中」へ。下限より遅れていれば前へ、上限より進んでいれば戻す：網の基準がまだ証していない間は跳ばし（step）、その後は `clock_adjust_wall` で滑らかに（slew の上限と、入りきらない差は跳ばす規則は §3.4）。単調時計と起きている時計は動かない。呼び手（RTC、Hyper-V の時刻の同期）を新しい口に直す。
5. **組んだ時刻の下限**（§3.7）。カーネルを組んだ時刻を起動の時に下限として一度渡す（組みの規則で時刻を埋める。毎回の組みで変わる値が増分の組みを壊さない形で）。
6. **Hyper-V の `tz_offset` を消す**（§3.9）。`kernel/src/vm/hv/hv_util.c` は host の UTC を区間の口で証すだけ。`vm/` の外に hypervisor の判定を書かない。

### 仕様と資料
- RFC 8536（TZif）は手元に無ければ、zip の中の TZif と Go の `time` の読み手の注釈（`D:\Programes\cloned repos\go\src\time\zoneinfo_read.go`、BSD の許諾）で形を照らす。読むのは形のためで、コードは写さない。
- CMOS の RTC は今の `dev/refclock.c` の注記の資料のとおり。
- Linux・BSD・NT ほか、OS のソースを読まない・写さない。GPLv2 だけのコードを入れない。

### 決まり
- 持ち主の単位で消してから建てる。古い道を残して新しい道を足さない。shim（何もしない関数、渡すだけの包み、偽の環境）を作らない。名前だけの口を作らない。
- 決め打ちの上限を置かない。時間の定数は仕様の値か測った値で出典を注記に。待ちは割り込みか事象で起こされる形にし、決まった間隔の見回りや回数の spin を作らない。
- GUI が先：設定は窓で変え、変えた瞬間に効く。ユーザーにコマンドを打たせない。
- 自分の持つファイルの外は、上の仕事が名を挙げた所だけ、口を変えるための最小の行だけ。`mm/` には触れない。
- コードの注記は周りに合わせて英語。今あるコードの書き方（名前、注記の濃さ）に合わせる。
- 編集は Edit・Write で。シェルや Python でファイルを書き換えない（この Windows の Python は LF を CRLF に変える。生成の道具が書く出力は `newline='\n'` かバイナリで）。シェルは Bash（Git Bash）。探すのは `rg`。
- 組んで確かめる：作業木の根で `python -X utf8 scripts/build.py -j 8 kernel` と、libc・設定アプリ・表の生成が組めることを `user` の目標で（出力は本体の `build/wt/<作業木の名>/`）。警告を増やさない。QEMU は起こさない、媒体（img）は作らない（本体が取り込んで起動する）。表の読み手はホストで回せる検査を `tests/check_*.py` の形で作る（幾つかの zone と移り目の前後、末尾の規則の年）。
- 作業木の枝にコミットする（題は日本語で「段 T1：何をしたか」、本文の最後に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`）。main へ取り込まない。push しない。
