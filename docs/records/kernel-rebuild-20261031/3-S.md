### 仕事
3-design.md §4.2 の契約どおりに建て直す。要点：

1. **syscall の表。**
   - `sys/syscall.c` に残すのは入口と表だけ。
     - 入口 `syscall_dispatch`：kill の確かめ、割り込みを開く、表を引く、呼ぶ。
     - 表：番号から手続きへの一つの const の表。`[SYS_X] = sys_x` の指定の初期化子で書き、穴は NULL で `N_ERR_UNSUPPORTED` を返す。
   - 手続きの型は一つ（六つの 64 bit の引数）。
   - 手続きは持ち主のファイルへ移す：process・app、thread、wait・address_wait、events、channel、object、stream・log、fs（document・entry・folder）、wm、net、pciuser・dma、gpu（`SYS_GPU_*`。実装は `vm/virtio_gpu.c`、ユーザーの指示で残す）、音、random、mm、時計、電源、時間帯。
   - 番号の範囲で振り分ける `wm_syscall`・`net_syscall` は消す。
   - 手続きの宣言は `sys/syscalls.h` 一つに並べる。利用者の記憶の写し（`copy_from_user`・`copy_to_user`・`user_str`・`user_string` など）は `sys/usercopy.c` へ。
2. **番号。**
   - 変わらない呼出しは今の番号のまま。消した番号は空けたまま（abi.h の冒頭の注釈の決まり）。
   - Go と Rust の移植の差分が番号を写している。写しは `common/abi.h` からホストの道具（`scripts/` の Python）で生成し、Makefile の生成の規則に入れる。生成物は生成元から作り、空の build/ から組んでも通ること。
   - 移植が消えた番号を持っていれば、ここで直す。
3. **64 bit の番号と錠の無い登録。**
   - thread と app の番号は 64 bit。1 から数え上げ、使い回さない。
   - 番号から物を引く登録は、2b-O の epoch で読む錠の無い表にする（2c の残り「`thread_lock` を錠の無い登録へ」をここで閉じる）。
   - `thread_lock` の残りの役（process の thread の一覧、親子のつながり、`process_space_end` の空間の参照）は process ごとの錠へ割る。割れないものは理由を書く。
   - ps の一覧は登録を epoch の下で歩く。
   - ABI の `SYS_THREAD_ID`・`SYS_APP_ID`・`n_procinfo` の `pid`・`ppid` などを 64 bit に。libc と使い手（tests・apps・ports）を直す。
4. **起動の塊。**
   - アプリの入口は rdi に一つの指 `const struct n_start *` を受ける。欄：版と大きさ、argc・argv、起動の設定の列、時計の頁の番地（3-T が値を入れる。今は 0）、主 stack の範囲（3-V の値）。新しい欄は末尾に足す決まりを注釈に書く。
   - 直すもの：`crt0.asm`、`__libc_start`、`sys/proc.c` の積み方、Go・Rust の入口。
5. **`n_cpuinfo`。**
   - 常に 0 の欄と常に立つ旗を、欄ごと消す：`worker_cpus`・`parallel_jobs`・`worker_chunks`・`N_CPU_AP_WORKERS`・`N_CPU_SSE2`・`N_CPU_AVX`・`N_CPU_USER_THREADS`。
   - 使い手を直す：`tests/cpuinfotest.c`・`tests/mlfqtest.c`・`user/apps/sysmon.c`・`tests/check_navigator_native.py`・`ports/rust` の差分・`docs/nocturne-native-abi.md` §9。

### 決まり
- 持ち主の単位で消してから建てる。
  - 古い道を残して新しい道を足さない。
  - shim（何もしない関数、渡すだけの包み、偽の環境）を作らない。名前だけの口を作らない。
  - 表から呼ぶ手続きが、別の手続きを呼ぶだけの包みにならないようにする。今の `sys_*` が持ち主の関数を呼ぶだけなら、持ち主の関数を手続きの型にする。
- 決め打ちの上限を置かない。待ちは割り込みか事象で起こされる形にし、決まった間隔の見回りや回数の spin を作らない。
- 核は横取りされる。利用者の記憶は写しだけで触る（SMAP）。spinlock の下で写さない。
- 自分の持つファイルの外は、上の仕事が名を挙げた所だけ、口を変えるための最小の行だけ。
- コードの注記は周りに合わせて英語。今あるコードの書き方（名前、注記の濃さ）に合わせる。
- 編集は Edit・Write で。シェルや Python でファイルを書き換えない（この Windows の Python は LF を CRLF に変える。生成の道具が書く出力は `newline='\n'` かバイナリで）。シェルは Bash（Git Bash）。探すのは `rg`。
- 組んで確かめる：
  - 作業木の根で `python -X utf8 scripts/build.py -j 8 kernel` と `user`（出力は本体の `build/wt/<作業木の名>/`）。
  - Go・Rust の移植は、道具（`tools/go`・`tools/rust`）があれば組む。
  - 警告を増やさない。
  - QEMU は起こさない（本体が取り込んだ後に起動して確かめる）。媒体（img）は作らない。
