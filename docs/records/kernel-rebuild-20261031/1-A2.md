## 報告（書き手の最後のメッセージ、全文）

A2（割り込みの層）の報告

結論：割り込みの層を、CPU ごとの vector の表・x2APIC だけ・IOAPIC がすべての GSI を持つ形に建て直しました。作業木の枝にコミットは 1 つ（84f085d5）です。`kernel` の目標は警告なしで組めました。QEMU は起こしていないので、動くことは未確認です。

## 1. 消したもの
- **xAPIC の道：** MMIO の LAPIC、`lapic_ident`、`lapic_present`・`lapic_addressable`、ICR の配達の状態を待つこと。旧名の `lapic_send_ipi`・`lapic_current_id`・`lapic_eoi`・`lapic_init*` も消しました。
- **系に一つだった vector の表：** `irq_vector_alloc`・`irq_vector_free`・`vector_register`・`irq_register`。
- **装置ごとの決め打ちの vector：** `VEC_XHCI`・`VEC_NVME`・`VEC_RTL`・`VEC_VMBUS`、smp.h の VEC の定義。
- **割り込みの順：** EOI を処理の前に送っていた順。
- **8259 を使う道：** `pic_mask`・`unmask`・`eoi` など。8259 は移して全部覆うだけ（irq.c の `pic_disable`）にしました。
- **PS/2（i8042）の全部：** `ps2_lock`・`kbd_irq`・マウス・`ps2_setup`・`ps2_resume`、`vm_ps2_flips_y`。
- **PCI の古い口：** `pci_msi_enable`・`pci_msi_disable`・`pci_msix_*`・`pci_interrupt_dest`・`pci_msi_given`。
- **rtl8125 の退き道：** INTx・8259 へ逃げる道を消しました。
- **AMD-Vi の任意だった道：** `iommu_amd_x2apic_conflict`・`ivhd_next`、64 bit の IRTE の道、XT と GA を任意にしていた道。
- **Intel の任意だった道：** EIM を任意にしていた道。
- **その他：**
  - hibernate.c の `pic_mask` の輪。
  - alarm.h の `alarm_interrupt` の宣言（alarm.c の static にした）。
  - `ioapic_isa_to_gsi`（名を `ioapic_isa_gsi` に改めた）。

## 2. 建てたもの（口と約束）
- **`arch/irq.h`・`arch/irq.c`（新）：**
  - 口：`irq_request_msi`・`irq_request_msi_block`・`irq_request_gsi`・`irq_request_system`・`irq_free`・`irq_set_cpu`・`irq_target`・`irq_msi_message`・`irq_msi_writer`・`irq_regs`・`IRQ_CPU_ANY`、`struct irq_spec`（`handler`・`thread`・`context`・`node`）、`enum irq_result`（`IRQ_NONE`・`IRQ_HANDLED`・`IRQ_WAKE_THREAD`）。
  - vector の表は CPU ごと。装置の vector は 0x30〜0xEF、系の vector は 0xF0〜0xFE で全 CPU に一つの表です。系の vector は `VEC_MCE_THRESHOLD` 0xFA、`VEC_TIMER` 0xFB、`VEC_RESCHED` 0xFC、`VEC_TLB_SHOOTDOWN` 0xFD、`VEC_APIC_ERROR` 0xFE、`VEC_SPURIOUS` 0xFF。0xF0〜0xF9 は空けてあります。
  - CPU の選び方：装置の node の中で、装置の vector が一番少ない CPU。割り込みが名指しできる CPU だけを選びます。APIC ID が 255 を超える CPU は、IOMMU の割り込みの付け替えが 32 bit の宛先を運べるとき（`iommu_irq_wide`）だけです。
  - 割り込みの扱い：
    - 処理は割り込みの stack の上で走り、EOI はその後（SDM 13.8.5）。
    - `IRQ_WAKE_THREAD` を返すと、irq ごとの thread（irq の CPU に `kthread_create_on` で縛る）が走ります。
    - level の線は、起こした thread が全部済むまで覆います（`ioapic_hold`）。
    - level の線は共有できます。edge の線は共有しません。
  - `irq_free` は、どの CPU でもその処理が走っていない（これからも走らない）ことを確かめてから戻ります。確かめ方は CPU ごとの処理の回数の数え（`wait_dispatch`）です。
  - 移しの約束：
    - MSI は書き手（`irq_msi_writer`）が新しい message を書きます。
    - GSI は IOAPIC の項目を書き直します。
    - 古い slot は次の移しか解放まで残し、途中の message を受けます。
    - 塊の irq と系の vector は移しません。
- **`arch/apic.c`：**
  - x2APIC だけです。IPI は topology の CPU の番号で送ります（`apic_send_ipi`・`apic_send_ipi_set`（論理の cluster ごとに 1 回の書き込み）・`apic_send_ipi_others`・`apic_send_nmi`・`apic_send_init`・`apic_send_startup`）。
  - CPU ごとの設定は `apic_init_cpu` です。MADT の LAPIC の NMI の入力を守り、LINT0 は覆います。
- **`arch/ioapic.c`：**
  - すべての GSI を持ちます（IOAPIC の数にも pin の数にも上限なし）。MADT の ISO を守り、SCI も IOAPIC を通します。
  - 口：`ioapic_route`・`ioapic_unroute`・`ioapic_hold`・`ioapic_gsi_owned`・`ioapic_gsi_signal`・`ioapic_isa_gsi`・`ioapic_remap`・`ioapic_mask_all`・`ioapic_suspend`・`ioapic_resume`。
- **`arch/idt.c`：** #PF は CR2 を読んでから、IF が立っていたときだけ割り込みを開けます。
- **`dev/pci.c`・`pci.h`：**
  - 口：`pci_irq_enable(d, specs, count, irqs)`・`pci_irq_disable`・`pci_msi_max_vectors`・`pci_msix_max_vectors`。
  - MSI-X を先に使い、項目ごとに層の選んだ CPU へ送ります。項目は書く間は覆います（PCI LB 3.0 6.8.3.5）。
  - MSI は 2 の冪の揃った塊を一つの CPU に置きます。
  - 移せるもの：MSI-X の項目と、項目ごとに覆える単独の MSI。
  - `pci_irq_disable` は、付け替えが消えたと確かめられないと false を返し、irq を解放せずに持ち続けます。
- **`dev/acpi.c`：**
  - `_PIC(1)` を `_INI` より前に呼びます（`uacpi_set_interrupt_model`）。
  - `acpi_pci_gsi` を新しく書きました。`_PRT` を引き、上流の bridge では swizzle（PCI-to-PCI Bridge 1.2 9.1）、link の `_CRS` も読みます。
  - SCI は `irq_request_gsi` で取ります。
- **上限とその出所：**
  - 一つの CPU の装置の vector は 0x30〜0xEF（x86 の vector は 256、0〜31 は例外。SDM 6.2）。
  - MSI の塊は最大 32（PCI LB 3.0 6.8.1.3）。
  - pciuser の `CLAIM_VECTORS 32`（ABI の 32 bit の語で、MSI の最大とも同じ）。
  - AMD の event の `specs[32]`（message の番号が 5 bit）。
  - 前からあり、使い続けた上限：acpi.c の `LINKS_MAX 32`・`PCI_DEPTH_MAX 32`、iommu_amd.c の `IRT_LOG2 5`（装置ごとに 32 項目）、iommu_intel.c の `IRT_ENTRIES 4096`。IOMMU の上限は私の持ち物の外なので残しました。

## 3. §4.2 から外れた所と理由
- **設計に無い口を足した：** `irq_request_msi_block`（MSI の複数の message）、`irq_target`・`irq_msi_writer`（付け替えと移し）、`irq_regs`（標本の取り手のため）、`IRQ_CPU_ANY`。
- **cpu の引数は厳しい：** 指定した CPU が使えなければ、別の CPU を選ばず NULL を返します。
- **cross-call の vector は定義していない：** 0xF0〜0xF9 は空きのまま。A1 のために `VEC_MCE_THRESHOLD` 0xFA だけ定義しました。
- **PCI の node は -1：** `_PXM` を読む口が無いためです。
- **眠りの順：** SDM 13.12.7 の順（irq_suspend → ioapic_mask_all → apic_init_cpu → irq_resume）にしました。
- **IOMMU：** `iommu_irq_wide` を足しました。AMD は XT・GA を必須に（2.2.5.3）、Intel は常に EIM にしました。
- **PCI の口を替えた：** 新しい口 `pci_irq_enable`・`pci_irq_disable`。
- **`acpi_pci_gsi` は新しく書いた：** 前のコードには無かったためです。
- **`input_init` を残した：** PS/2 は消しましたが、眠りの後に修飾キーを戻す pm の hook だけが残ります。
- **SynIC：** `irq_request_msi` の vector を `hv_core_init` を走らせる CPU に取り、移しません。
- **pciuser の戻り値：** message を一つも書けないとき、`-N_ERR_UNSUPPORTED` ではなく `-N_ERR_BUSY` を返します。
- **e1000・tulip：** `_PRT` の道が無いと立ち上がりを失敗にしました（前は決め打ちの線）。ac97 は道が無ければ前からの alarm の道を使います。

## 取り込みの記録（本体、2026-10-31）
- 枝を main（D・A1 の後、134d49ad）へ載せ直し、main を 3ac85a92 へ早送りした。
- smp.c は A1 の形（自前の INIT・STARTUP、一つの締め切り）に、A2 の口（CPU の番号で送る `apic_send_*`）を入れた。x2APIC は全ての APIC ID を指せるので、`lapic_present`・`lapic_addressable` の分かれ道と INIT の送り損ねの扱いを消した。A2 の古い起こし（limine の MP、selftest）は A1 の側で既に消えていたので取らなかった。
- x2APIC へ入るのは apic.c の `apic_init_cpu` だけにした（cpu.c の `cpu_setup` にあった同じ手順を消した）。wake.asm の xAPIC の道・wake.c の id の欄は A1 の版に無い。
- MCA の閾値の割り込みは `irq_request_system(VEC_MCE_THRESHOLD)`、記録の自分への IPI は新しい系の vector `VEC_LOG`（0xF0）を `irq_request_system` で取り `apic_send_ipi(cpu_current_index(), VEC_LOG)` で送る。serial は `irq_request_gsi`（信号の形は IOAPIC が知るので、serial.c の `gsi_trigger` と level・low を消した）。
- `irq_nesting` を消し、isr.asm が `preempt_count` の割り込みの部分を増減する。idt.c の NMI と #MC は NMI の部分を増減して `smp_nmi`・`cpu_machine_check` を呼ぶ。vmm.c・sched.c の ASSERT は `in_interrupt()`。
- idt.c：`entry_load` の EFER.SCE（`cpu_setup` と重複）と `idt_init` の中の `entry_load`（IDT の二度読み）を消した。`smp_panic_nmi` は smp.c の中の static。
- 組み：警告なし。QEMU（窓付き一台、USB の入力）：起動の行は A1 の回と同じ（PS/2 が消え、IRQ が GSI の呼び名に、xHCI の MSI は CPU 2 へ）。USB の指とキーで Terminal を開いて `help` を打てた。
