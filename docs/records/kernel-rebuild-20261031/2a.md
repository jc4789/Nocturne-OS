### 頼むこと（2-design.md §2 のとおり）
1. `struct task` を `struct process`（`sys/process.h`・`process.c`）と `struct thread`（`sys/thread.h`・`thread.c`）に分ける。今の `struct task` の欄を、持ち主ごとにどちらかへ移す。thread の sched の欄は、今の欄をまとめた一つの型の欄にする（S が後で中身を替える）。待ちの欄も同じ（W が替える）。
2. kernel thread が process を持つかを、呼ぶ側（`kthread_create`・`kthread_create_on` の使い手、irq の thread、pm、vmalloc、log の読み手など）を読んで決め、注記に書く。
3. pid と tid の割り当て：上限の定数なし、`task_find`（名は替えてよい）は O(1)。今の `lib/idtable` が合えば使い、合わなければ ID の割り当ての部品を `kernel/src/lib/` に建てる。使い回しの前に間を置くかを決めて注記。
4. thread の数の上限（今の `sched.c` の `count >= 128`）を消す。
5. 終わりの道：process の最後の thread が終わると handle の表を閉じ、各持ち主の後片付けはその object の close で行う。`sched.c` から `pci_user_is_claim`・`wm_process_exit`・`net_process_exit`・`net_task_exit`・`sys_shared_cleanup` の直の呼出しを消し、それぞれの持ち主の object の close へ移す。handle でない物（窓・PCI の claim・接続）を持つ持ち主には、handle の object を持たせる。そのために `gui/wm.c`・`net/net.c`・`dev/pciuser.c`・`sys/syscall.c`・`sys/proc.c` に触れてよい（後片付けを object の close へ移す最小の行だけ）。
6. `sched.c` を割る：run queue と schedule と idle は `sys/sched.c`、thread と process の一生は `thread.c`・`process.c`、待ち行列と mutex と眠りは `sys/wait.c`・`wait.h`、番地の待ちは `sys/address_wait.c`・`address_wait.h`。待ちと番地の待ちの中身（算法）は変えない（W が建て直す）。run queue の算法（`kei.c`）も変えない（S が建て直す）。各ファイルは使う見出しを直に include し、まとめて渡すだけの見出しを作らない。
7. `task_printf_stderr` は console の stream の持ち主（`sys/stream.c`）へ移す。
8. `struct task` と `current_task` を使う約 27 のファイルを新しい型に合わせる（機械的な置き換え。意味を変えない）。

### 決まり
- 持ち主の単位で消してから建てる。古い名を残す別名・包み・渡すだけの関数を作らない（`struct task` を `typedef` で残さない）。名前だけの口を作らない。
- 決め打ちの上限を置かない。待ちは割り込みか事象で起こされる形で、決まった間隔の見回りや回数の spin を作らない。
- ABI（`common/abi.h`）は変えない。アプリから見える振舞いを変えない。
- Linux・BSD・NT ほか OS のソースを読まない・写さない。GPLv2 だけのコードを入れない。
- コードの注記は周りに合わせて英語、今あるコードの書き方（名、注記の濃さ）に合わせる。
- 編集は Edit・Write で。シェルや Python でファイルを書き換えない（この Windows の Python は LF を CRLF に変える）。シェルは Bash（Git Bash）。探すのは `rg`。

段 2a の報告

1. 消したもの
- 型と欄：`struct task` を丸ごと消した。`is_thread`・`is_user`・`is_idle`・`app_launched` の欄もない。`TASK_*` は `THREAD_*` に替えた。
- 錠・一覧・数：`task_lock`・`task_list`・`next_pid`・`task_count`。
- 上限：`task_thread_create` の thread の数の上限（`count >= 128` → `-N_ERR_NOT_READY`）。
- task の関数：`task_alloc`・`task_free`・`task_find`・`task_exit`・`task_kill`・`task_kill_tree`・`task_process`・`task_wait`（呼び手なし）・`task_thread_create` ほかの `task_*`。`task_printf_stderr` は stream へ移した。
- sys/proc.c：`proc_user_pages`・`kpush`、`proc_spawn_simple` の parent の引数。
- 終わりの片付けの関数：`pci_user_is_claim`（pciuser.c/h）、`wm_process_exit`（wm.c/h）、`net_process_exit`・`net_task_exit`（net.c/h）。
- object.c/h：`handle_table_next`・`handle_table_free`。
- sched.c から外へ移したもの：一生、待ち、番地の待ち、kstack の溜め、reaper。

2. 建てたもの
- struct process（sys/process.h）：
  - 識別と状態：pid（主 thread の tid）・name・main・threads（他の thread の一覧）・exiting・ended・exit_code。
  - refs：終わるまで 1、他の thread の記録ごとに +1。最後に放した者が主 thread の記録と一緒に解く。
  - 家族と記録：parent・children・sibling・app・wait（thread の終わりの待ち）。
  - 資源：handles（`struct handle_table`）・vmm_space。
  - 空間の配置：space・space_ops・space_ended・mmap_next・mmap_holes・low_base・low_next・low_holes・shared_mappings。波 3 で mm へ移すまでここに置くと注記した。
- struct thread（sys/thread.h）：
  - fpu・tid・name・process（核の thread は NULL）。
  - killed・kill_code・joining・detached。
  - ksp・kstack・fs_base・gs_base・user_stack・user_stack_size・net_setup_cancel・start_ns。
  - sched（`struct sched_entity`、sys/sched.h：state・idle・cpu・cpu_ns・kei・allowed）と wait（`struct thread_wait`、sys/wait.h：queue・next・alarm・timed_out・phys・seq）。
  - 繋ぎ：id（登録の表）・all_next/prev・process_next/prev・dead_next。
- ID：
  - tid は lib/idtable（伸びるハッシュ）に登録し、`thread_find` は O(1)。lib に新しい部品は建てていない。
  - tid は [1, INT32_MAX] を巡って空いた番号を取る（`tid_take`）。連続した count+1 個のうち使用中は高々 count 個なので、探しは count+1 回以内で終わる。上限の定数はない。
  - pid は主 thread の tid（`process_find` は主 thread で、始まっていて終わっていない物だけを返す）。
  - 使い回しまでの間：同じ番号は 2^31 個を配り終えるまで戻らない。
- 終わりの道：
  - 主でない thread の `thread_exit`：
    1. net_setup_cancel を閉じる。
    2. process が終わり始めていなければ、利用者の stack を返す。
    3. `vmm_leave` して ZOMBIE になる。detach 済みなら reaper へ渡し、そうでなければ join を待つ。
  - 主 thread の `thread_exit` は `process_end` へ進む：
    1. `thread_end_others`：他の thread を全部止め、終わった記録を解く。
    2. `handle_table_close`：`closes_first` の object（PCI の claim）、他の番号つき handle、保持の handle の順に閉じる。
    3. 空間の終わり（`sys_shared_cleanup` → vmm_space を NULL → `vmm_space_end`）。
    4. `proc_app_ended`、子を孤児にし、親の一覧から外れ、主 thread を reaper へ渡す。
  - 持ち主ごとの片付け：
    - 窓：窓の handle の close（`win_close`）で消える。
    - 網：pid ごとの UDP・TCP は、新しい保持の handle の close（`owner_close`）で解く。保持の handle とは、net.c の `struct net_owner` を表の held の列に置く番号なしの handle（`handle_hold`／`handle_held`）。ソケットの syscall の初めに一つ作る。
    - PCI の claim：`claim_ops.closes_first = true` で先に閉じる。
- ファイルの割り方：
  - sys/sched.c：run queue・schedule・idle・`sched_thread_add/bind/remove`。
  - sys/thread.c：thread の登録・始め・join・detach・終わり・kill・reaper・kstack の溜め。
  - sys/process.c：process の始め・終わり・家族・kill。
  - sys/wait.c・wait.h：待ち行列・mutex・眠り。名の替えだけの移し。
  - sys/address_wait.c・.h：番地の待ち。名の替えだけの移し。旧の行と diff で照らした。
  - `task_printf_stderr` は sys/stream.c の `stream_error_printf(struct process *, ...)` へ移した。
  - 各ファイルは使う見出しを直に include し、まとめて渡すだけの見出しは作っていない。

3. 2-design.md §2 から外れた所と決めごと
- 核の thread は process を持たない（`thread->process == NULL`、`process_current()` は NULL）。
  - 理由：呼ぶ側（irq の thread・pm・vmalloc・log の読み手・reaper・net・usb・store の書き手・keep など）を読んだ。どれも核の自前の状態だけを扱い、自分の handle の表を使わない。表を使う口（handle_install・handle_get など）の呼び手は、どれも syscall の道だった。
  - NULL を見る所：shared_fault・vmm の頁違反・pci の `reset_cancelled`・schedule の vmm_switch。
  - 核の thread から表の口を呼ぶと、今は落ちる（旧は空の表があった）。
- `sys_shared_cleanup` は sched からは消えたが、process.c の空間の終わり（`process_space_end`）から直に呼んでいる。§2 の「object の close へ」とは違う。
  - 理由：共有の写像は空間の配置の一部で、handle ではない（handle を閉じても写像は残る）。空間が消える前に外す必要がある。波 3 で配置を mm へ移す時に、持ち主もそこへ移すのが筋。
- ID の使い回し：2^31 を巡った後に番号が戻る。
  - docs/nocturne-native-abi.md の 240 行・300 行の「識別子は再利用しない」と食い違う。
  - 旧は INT32_MAX に達したら task を作れなくなるだけで、使い回しもしなかった。差が出るのは 2^31 回の生成の後だけ。
  - 本体の判断を求む：ABI の文を「2^31 巡るまで再利用しない」に直すか、巡らずに止める形へ戻すか。
- 番号のずれ：旧は idle0 が pid 0 で、番号は 0 から振られた。新は tid が 1 から始まり、idle0 も 1 から番号を取る。
  - 一覧で見る番号は旧より 1 ずつ後ろにずれる見込み。
  - 特定の pid を前提にするコードは、rg で探して無かった。
- 窓の振舞いの差：旧の `wm_process_exit` は作り手の pid の窓を全部消した。新は窓の handle の最後の close で消える。
  - 窓の handle を他のアプリへ送ると、作り手が終わっても窓が残る。
  - 今その送りをする利用者のコードは見つけていない（未確認）。
- `process_kill` は process（主 thread の pid）だけを探す。
  - 旧の `task_kill` は、主でない thread の tid でもその thread を殺せた。核の task には DENIED を返した。
  - 呼び手は二つで、どちらも process の pid しか渡さない：sys_app_stop（戻り値を見ない）と pciuser（ログだけ）。アプリから見える差は無い。
- 起動の道の直し：起動したアプリの pid を `process_start` の前に保つようにした（旧は start の後に t->pid を読んでいた。起動された側が先に終わると解いた記録を読む恐れがあった）。
- `thread_exit` が net_setup_cancel を自分で閉じる（旧の `net_task_exit` の代わり）。
- §2 との小さな違い：process に thread の数の欄は持たず、要る所（記憶の報告）で一覧を数える。眠りの alarm は thread_wait に、CPU の時間は sched_entity に置いた。
- sched_thread_remove が CPU を離れるのを pause で待つ形は、旧の `off_cpu_wait` のまま（S が建て直す範囲）。
