### 頼むこと
1. **速さの源を作り直す。**
   - 実機（hypervisor の印なし）：AMD（vendor が AMD）で、HWCR の TscFreqSel が 1、PStateDef[0] の PstateEn が 1、DID が表の正しい値なら、速さ = 200 MHz × FID ÷ DID（整数で正確に）。読めなければ、Nocturne の下限を満たさない機械として起動で止める（理由を言う panic）。MSR を読む所はどこが持ち主かを決めて注記する（CPUID の唯一の読み手は `cpu.c`。P0 は CPU が自分の TSC について言うことなので、`cpu_features` の欄にするのが今の形に近い）。
   - VM（hypervisor の印あり）：今どおり hypervisor が登録した値（`clock_register_tsc_hz`、vm/ の後ろ）。VM の中で PStateDef を読まない（客の TSC は TSC ratio で替わりうる）。
   - **消す**：Intel の CPUID 15h の枝と `cpu_features.tsc_crystal_hz`、`dev/refclock.c`・`refclock.h`（HPET と ACPI PM タイマー）とその使い手、clock.c の参照の数え手の測り（`measure_boot`、参照の標本、`RATE_MEASURED`）。HPET の表の読みが acpi.c など他にあれば、使い手が他に無い限り消す。
2. **不変 TSC を実機で必須にする。** `cpu.c` の表で、hypervisor の印が無いのに不変 TSC が無ければ起動で止める（WHPX のように hypervisor が印を隠す時は通す）。clock.c の「the TSC is not invariant, so the clock goes with its changes」の道を消す。
3. **比べる相手を RTC にする（速さの直し）。** 名目の P0 は spread spectrum・BCLK・水晶のずれを知らない。今の clock.c は参照の数え手を倍の窓で標本にして速さを直し、別に RTC の秒の境を探りで見つけて壁の時計を合わせている（`edge_*`）。この二つを一つにする：RTC の秒の境（32.768 kHz の独立した水晶）を基準に、境を探りで狭め続け、最初の境からの窓が倍になるたびに、その窓での TSC の速さとその幅（境の不確かさ ÷ 窓）を出す。今の discipline の規則（新しい速さはその時の読みから始め、時計は飛ばない・戻らない。合えば幅の小さい方を取り、合わなければ最後の窓だけの速さで始め直す。誤差の和を記録に出す。`alarm_clock_changed`）はそのまま使う。探りは alarm で（決まった間隔の見回りにしない。窓が倍になる形）。VM の中でも同じに走らせる（VM の RTC は host の壁の時計に従う）。眠り（S3・休止）からの戻りの扱い（`clock_resume`）も合わせる。
   - 後で NTP（網の時刻）がこの基準を継ぐ。NTP は今は作らないが、基準を一つの口（「秒の基準」：境の時刻と幅を渡す）にして、NTP が後から同じ口へ入れる形にする。名前だけの口は作らない（RTC が今その口の本物の実装）。
4. **記録の行**：起動で `clock: TSC <MHz> by the P0 P-state (FID x, DID y)` のように源を言う。RTC の窓ごとの直しは今の行の形（ppb の幅、誤差の和）。
5. 地図 `.claude/rules/map.md` の `sys/` の `clock` と `dev/` の `refclock` の記述、`README.md` の時計の節を今の形に直す。

## 依頼の変更（本体が書き手へ送った文、2026-10-31）

依頼の 3（比べる相手を RTC にする）を取り消し、次の形に替えてください。1・2・4・5 はそのまま。

理由：RTC の 32.768 kHz は音叉の水晶で温度に対して放物線で大きくずれ（筐体が温まると十数 ppm）、MHz の水晶（HPET の源）の方が速さの基準として良い。RTC の秒の境は CMOS の I/O ポートを LPC・eSPI ごしに読み、SMI の遅れも受け、境が揃うまで数十秒かかる。HPET は MMIO の 64 bit の数え手で、一回の読みで済み、10〜20 ms で spread spectrum や BCLK の外れを測れる。

新しい形：
- 速さの始まり：実機は P0 の名目（FID/DID×200 MHz）、VM は hypervisor の登録した値。起動の瞬間にこれで時計を始める（参照の測りを待たない）。
- 直し：HPET を参照に、今の clock.c の倍の窓の discipline（合えば幅の小さい方、合わなければ最後の窓だけの速さで始め直す、時計は飛ばない、誤差の和を記録）を起動からそのまま走らせる。始まりの速さは P0 なので、`measure_boot` の「幅が 2^-14 になるまで待つ」最初の測りは要らない。最初の窓は短く始め（spread spectrum の −2500 ppm 程度の外れが ms で分かる長さ）、倍にしていく。VM の中では hypervisor の値を使い、HPET で直さない（今どおり）。
- 消す：ACPI PM タイマー（I/O ポートの数え手）。`dev/refclock.c` は HPET だけの持ち主に縮めるか、HPET の読みを clock.c の参照の部品として置くか、持ち主を決めて注記する。HPET が無い実機では、P0 の名目のまま走り、そう記録に出す（後で NTP が直す）。
- RTC は壁の時計だけ（今の `edge_*` の役のまま）。速さの基準にしない。
- 基準の口：NTP が後で入る所は「速さの参照」（今は HPET が本物の実装）と「壁の時刻の参照」（今は RTC）。名前だけの口は作らない。

（変えた理由の元：ユーザーが見せた Google の批評。音叉の水晶の温度特性、CMOS ポートの遅さ、HPET の MMIO の簡単さは正しいと本体が判断した。HPET の源が FCH の MHz の水晶だという点は AMD の資料で確かめていない。）

## 2 建てたもの

### 速さの源（`clock_init`）
- 登録された値があればそれを使う。vm/ の Hyper-V が `clock_register_tsc_hz` で登録したもので、述べられたとおりに使い、HPET では直さない。
- 無ければ P0 を使う：`CPU_COF_UNIT_HZ`（200 MHz）×`p0_fid`÷`p0_did`。mult は分数のまま整数で求める。
- どちらも無ければ panic「the hypervisor registers none」。
- clock.c は hypervisor を判定しません。P0 の欄を埋めるのは cpu.c で、hypervisor の印が無いときだけです。
- 起動の瞬間からこの速さで時計を始めます。速さの幅は `CLOCK_RATE_UNMEASURED`（UINT32_MAX）で、`clock_data.rate_bound` の意味もこれに変えました。

### P0 の読みの持ち主：`arch/cpu.c`
- 読むのは `cpu_features_init` の中で、hypervisor の印が無いときだけです。`tsc_p0`。
- 照らすもの：vendor が AMD、HWCR（C001_0015）の bit 24 TscFreqSel が 1、PStateDef[0]（C001_0064）の bit 63 PstateEn が 1、FID が 10h〜FFh、DID が表の正しい値。
- 外れたら `cpu: <brand> states no TSC rate Nocturne can use: <理由>` で止まります。
- 結果は `cpu_features.p0_fid`・`p0_did` の欄に入ります。
- 各 AP は `cpu_features_same` で同じ FID・DID かを照らし、違えばその CPU を入れません。
- 不変 TSC は optional の表で `HARDWARE(...)` の印にしました。hypervisor の印が無いのに欠けていれば、required と同じ panic の一覧に入ります。

### 直しの形（HPET を参照に、起動から）
- **窓**：最初の標本が錨です。最初の窓は、幅の各部が 2^-12 未満になる長さにしました。
  - 数え手の側は (1+2×jitter)×2^12 counts。
  - TSC の側は錨の読みの幅×2×2^12 を、今の速さで数え手の counts に換えたもの。
  - 長い方を取ります。幅はおよそ 2^-11（約 488 ppm）で、−2500 ppm 程度の spread spectrum の外れは最初の窓で分かる見込みです。HPET の読みが 1 µs なら数 ms になる計算ですが、測ってはいません。その後は倍にしていきます。
- **合う・合わない**：今の規則のままです。
  - 二つの幅の和の中で合い、幅が小さいときだけ採る。
  - 合わなければ最後の窓だけの速さで始め直す。
  - 時計は飛ばず戻らず、`alarm_clock_changed` を呼び、誤差の和を行に出す。
- **名目の速さの扱い**：幅を持たないので、最初の窓の値で必ず置き換わります。その時の誤差の和は、TSC の始まりから「名目と測った値の差÷測った値＋窓の幅」×時間です。
- **窓を始め直す時**：別の参照に替わった、眠りから戻った（`clock_resume`）、`clock_cpus_compare` で offset が変わった、のどれか。
- **標本の CPU**：標本の TSC はその CPU の offset を引いた時計の数えにしたので、CPU が替わっても窓は切れません。前は CPU が替わると始め直していました。
- **HPET が無い実機**：`clock: no HPET to measure the TSC against; it keeps the P0 P-state's nominal rate` と出し、名目のまま走ります。

### 速さの参照の口（NTP が後で入る所。今の本物は HPET）
```c
struct clock_rate_reference { const char *name; uint64_t hz_num, hz_den; void (*resume)(void); };
struct clock_rate_sample { uint64_t tsc_a, tsc_b; uint32_t cpu; uint32_t jitter; uint64_t count; };
uint64_t clock_rate_sample(const struct clock_rate_reference *ref, const struct clock_rate_sample *s);
```
- 契約：
  - 持ち主は自分の数えを、一つの CPU の TSC の二回の読みの間で取る。
  - 装置の wrap を越えて数えを伸ばして渡す。
  - 戻り値は時計が次の標本を欲しい時刻（monotonic の ns）。CLOCK_NEVER は「要らない」で、述べられた速さで走っているとき。
  - `resume` は `clock_resume` から呼ばれ、新しい数えを始めて標本を一つ渡す。
- HPET の持ち主は `dev/refclock.c` の `refclock_hpet_start`（`clock_init` が P0 のときだけ呼ぶ）です。
  - 自分の alarm で、時計の求める時刻か wrap の 1/4 の早い方に読む。32 bit の数え手のときだけ wrap が効き、64 bit なら無い。遅れは待ちの 1/64 まで許す。
  - jitter は 2（HPET 1.0a 2.4.1）。
  - S3 の後は ENABLE_CNF を立て直し、新しい数えを始める。

### 壁の時刻の参照の口（今の本物は RTC）
```c
int64_t clock_wall_proof(int64_t unix_ns, uint64_t by);
```
- 意味：「monotonic の時刻 by までに、時刻は少なくとも unix_ns だった」。
- 前に証されたより先を示した分だけ、壁の時計を進めます（戻さない）。`clock_set_wall`・`clock_adjust_wall` で始まり（起動か戻り）の後に動かされていれば、壁は動かしません。
- 戻りの後は RTC の境の探りが終わるまで、進めた分を眠っていた時間として起動からの時計にも足します。
- 使う所：起動の RTC の読み（`wall_init`）、秒の境の探り（`edge_found`）、`clock_resume` の RTC の読み。
- `clock_resume` は、眠る前の上限（`stop.rtc_up`）を `proofs.floor` に置いてからこの口を通します。このため眠りの時間の計算は前と同じ結果になります。
- RTC の境の探り（`edge_*`）の役は前のままで、RTC は速さの基準にしていません。

### 記録の行
- 起動で `clock: TSC 4700.000000 MHz by the P0 P-state (FID bch, DID 8h)` の形（数値は書式の例で、実機の値ではありません）。VM では `clock: TSC … MHz by Hyper-V`。
- HPET が見つかると `refclock: HPET at …` と `clock: the TSC measured against the HPET over windows that double from N us`。
- 窓ごとの直しは今の形：`clock: TSC … MHz within … ppb of the HPET over … ms (±… ppb); the clock within … ns of it`。

## 3 PPR 56713 の読みで本体と違う所
- **式**：p.38 の CoreCOF ＝ FID÷DID×200 MHz が正、という本体の読みに同意します。p.210 の「COF is defined as CpuFid * 5MHz」は最大 1275 MHz にしかならず、FID の表（Value×25）とも DID の表とも合いません。
- **DID の正しい値**（p.209–210 の表）：依頼文は「08h は VCO/1、0Ah〜2Ch は VCO/(値/8)」でしたが、表は次のとおりで、この表どおりに実装しました。
  - 08h は VCO/1、09h は VCO/1.125。
  - 0Ah〜1Ah はすべて値/8。
  - 1Ch〜2Ch は偶数だけで、1Bh〜2Bh の奇数は Reserved。
  - 2Dh〜3Fh は Reserved、01h〜07h は Reserved、00h は Off。
  - 本文には「Core supports DID up to 30h」ともありますが、表は 2Dh 以上を Reserved としているので表に従いました。
- **HWCR の bit 位置**：pdftotext の layout 出力では TscFreqSel が bit 17 の行に見えますが、これは段組みのずれです。Reset 値 0000_0000_0100_0010h と PyMuPDF の抜き出しで bit 24 と確かめました。依頼文どおりです。
- **PStateDef の注**：「All other fields … same value in each core of the coherent fabric」とあるので、AP の照らしはファームウェアの誤りへの守りです。
- **APIC timer**：56713 の 2.1.9 にも「may increment in units of between 1 and 8」があります。lapic_timer.c は 55898 の 2.1.12 を引いたままで、直していません（その行は持ち物の外の内容）。
