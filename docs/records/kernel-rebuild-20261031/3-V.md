### 仕事
3-design.md §3 の契約どおりに建て直す。要点：
1. 空間の記述を mm に一つ：範囲の木（`lib/span` の最長の空きの要約）、範囲の種類（無名の予約・確定、program の像、stack、共有記憶の物の写し）と権利と頁ごとの権利の表。`struct process` の配置の欄と syscall.c の `mmap_hole`・`space_op`・`shared_mapping` の鎖を消す。範囲の木は読み書きの mutex、頁表は頁表の頁ごとの錠。一つの大きな spinlock を残さない。頁表は触れた所だけ作り、空になった頁表の頁は撃ち落としの後に返す。予約は範囲の木の印で、葉を先に作らない。
2. 頁違反：`arch/idt.c` は利用者の頁違反で割り込みを開いてから mm を呼ぶ。範囲の種類で解き、眠れる（frame の確保、pager の待ち、記憶の圧の直接の回収）。無名は揃えば 2 MiB の大きな頁。pager の待ちは範囲の木の錠を放して眠り、起きたら引き直す。
3. 共有記憶の物（`struct shared_pages` の種類と寿命）・pager・program の cache を mm の部品へ。syscall.c には ABI の手続き（引数の写しと mm の口を呼ぶこと）だけを残す。`shared_lock` は物ごとの錠と範囲の木の錠に割れるか読んで決め、割れないものは理由を書く。`pciuser`・IOMMU との継ぎ目は口だけを保つ（中身は波 4）。
4. TLB：撃ち落としは空間を載せたことのある CPU の集合へ一度に。Zen 4 は PCID が Fixed,0（PPR 56713）。INVLPGB・TLBSYNC の有無と、PCID を使わないときの意味を APM vol3 と PPR 56713 で照らし、使えるなら IPI の代わりに。今の CPU ごとの PCID の席は、PCID を持つ CPU の資料と INVLPGB と両立する形を示せるなら残し、示せないなら消す。直写像は 1 GiB の頁。
5. 配置：主 stack の大きさの決め打ち（`USER_STACK_MAX`）をやめ、範囲の木の stack の範囲として伸びる上限を持つ。ASLR：無名の写しの領域の基と stack の位置を核の乱数で毎回変える。像は非 PIE なので動かさない（PIE にするかは 3-S・3-T で決める、と報告に）。ABI の振舞いを変えたら `docs/nocturne-native-abi.md` を同じコミットで直す。

### 決まり
- 持ち主の単位で消してから建てる。古い道を残して新しい道を足さない。shim（何もしない関数、渡すだけの包み、偽の環境）を作らない。名前だけの口を作らない。
- 決め打ちの上限を置かない（表の大きさは実際の数から。ハードウェアが決める数は出典つきで定数）。待ちは割り込みか事象で起こされる形にし、決まった間隔の見回りや回数の spin を作らない。
- 核は横取りされる。撃ち落としは spinlock の下と割り込みの中でしない。利用者の記憶は写しだけで触る（SMAP）。
- 自分の持つファイルの外は、3-design.md §3.6 が「触ってよい」と書いた所だけ、口を変えるための最小の行だけ。それ以外は触らずに報告に書く。
- コードの注記は周りに合わせて英語。今あるコードの書き方（名前、注記の濃さ）に合わせる。
- 編集は Edit・Write で。シェルや Python でファイルを書き換えない（この Windows の Python は LF を CRLF に変える）。シェルは Bash（Git Bash）。探すのは `rg`。
