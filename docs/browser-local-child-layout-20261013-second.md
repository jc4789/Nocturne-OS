# 動的挿入と同期寸法flushの局所化：第二考察

第一報の「局所なら速い」を無条件には採用せず、以下の反例を源と支持条件へ戻した。

1. :is(i:first-child)をuniversal subjectとして扱うとbodyの全既存forestへ再びfull cascadeする。必要な正のlogical subjectキーを再帰で確認し、:notや:hasのwitnessから現在のdynamic matchを推定しない。:emptyの外側sibling、末尾位置、sibling :hasの削除は別条件を保持。
2. absoluteでもauto/static inset、percentage/math、intrinsicなflex/grid/table/inline祖先、container/pseudo/list/atomic/Shadow/ownerは独立性を証明していないので全再建。明示純粋lengthの新枝でもrootをdirtyにし、既存layout入力key・font世代とoverflow再算出を通す。原nongenerated pseudo17のgeometry再利用と、新枝追加の実geometry更新を混同しない。
3. 原boxアリーナへ追記し続ける方式は採用しない。枝arenaの唯一ownerは生成root box、旧treeのcacheとnode/anchor借用を消してからarenaを最後に解放。parentのchild走査は解放前にnextを捕捉する。stage失敗は新枝だけ回収してから全再建へ戻るため、半公開枝を有効geometryへラベルしない。
4. queueのnodeは既存native文書arenaに属し、wrapperのfinalizerはnative nodeを解放しない。queueは同期publicationまでだけ使用し、adopted/別ownerを局所処理せず、文書破棄でvectorも回収する。新しい二重DOMやJS側の独立寿命表は追加していない。
5. 候補全組比較・pending removal再走査・appendごとの前方探索は大量変更で二乗になる。動的pointer索引と各親一回のmerge、dirty-path一回のpaint-alpha joinへ修理。validationには間引きnative checkpoint、stage前後には安全なキャンセル境界を置き、commitはallocation無しの一貫したchain変更とする。
6. 寸法getterは毎回本物の最新CSS/box/layoutを同期計算する。MO／CE／反応順、FIFO、作者取消、媒体PTSと供給経路を省略しない。ホスト候補20条件は実box生成・arena回収・実サイト速度を証明しない。

次は主担当の最新完全媒体で原17と追加child-list native経路、同条件実記事の初期本文・Timer675相当のflush・F12／上下wheel／動画進行を確認する。源だけの成功や古cadence画像を、この変更の受入へ昇格しない。
