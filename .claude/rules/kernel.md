# カーネルの領域に触れたとき

- **対称のカーネル。**CPU に役割の差は無い。どの CPU も自分の実行キュー（`sys/sched.c`）と idle thread を持ち、user の thread も核の thread（`kthread_create`）もどの CPU でも走り、CPU の間を移る。idle thread も守りの頁つきの核の stack で走り、bootloader の stack は入口で離れる（`sched_cpu_stack`）。syscall（`SYSCALL` → `syscall_entry`）・例外（`isr_exception`）・割り込みと IPI（`isr_interrupt`、CPU ごとの割り込みの stack の上）は起きた CPU で処理する（`arch/isr.asm`・`arch/idt.c`）。BSP へ回す道、AP の写し・読み取り区間・門は無い（消した名：`cpu_require_bsp`・`sched_enter_bsp`・`cpu_is_runner`・`ap_read_*`・`handle_peek`・`handle_install_locked`・`handle_take_locked`・`handle_table_find/reserve/add`・`events_watch_locked`・`syscall_ap`・`syscall_anywhere`・`isr_dispatch_remote`・`sched_quiesce_space`・`vmm_ap_*`・`net_ap_*`・`wm_state_ap`・`proc_app_result_ap`）。戻さない。
- **CPU が自分で行う手順は、その CPU に縛った thread で**（`kthread_create_on`・`sched_thread_bind`：縛った thread は均しの引きと押しでも、起こしの置き場所でも、その CPU を離れない）。眠り（`smp_suspend`・`wake_sleep`）は最初の CPU で走る：pm の thread は CPU 0 に縛ってある。
- **CPU ごとの状態は CPU ごとの変数**（`arch/percpu.h`）。CPU の数で配列を切らない（上限の定数は無い）。自分の CPU のものは `this_cpu`／`this_cpu_ptr`、ほかの CPU のものは `per_cpu(v, cpu)`。CPU を回る輪は `topology.cpus` まで。`this_cpu_ptr` で取った指の扱いは次の項。
- **核も横取りされる**（切り替えの点は `preempt_enable` で数が 0 に戻るとき、`irq_restore` で割り込みが開くとき、割り込みから核への出口、`sched_user_return`。旗は CPU ごとの `sched_resched`）。CPU ごとの状態を続けて使う区間は `preempt_disable`／`preempt_enable` で囲む（spinlock を取ると自動で止まる）。`this_cpu_ptr` の指は、横取りが止まっていない所ではいつでも別の CPU のものになりうる。ほかの CPU と同時に走る。`irq_save`／`cli` が閉じるのはその CPU の割り込みだけで、ほかの CPU との排他にはならない。共有の状態は持ち主の `struct spinlock`（`arch/spin.h`、`spin_lock`／`spin_unlock`、割り込みを閉じてあれば `spin_take`／`spin_give`）か `struct mutex`（`sys/wait.h`、眠れる。確保・写し・待ち・disk をまたぐ状態）で守る。spinlock を持つ間は眠らない・写さない・`mutex_lock` しない。長い核の処理は横取りに任せ、自分で `schedule()` を呼んで譲らない（横取りを止めた区間を長くしない）。mutex は FIFO の待ち手へ手渡し、kill では終わらない。
- **待ちは条件の lock の下で入る**。条件を変える者が持つ lock を取り、条件を見て、`wq_wait_locked(&wq, &lock)`（戻ったとき lock は持っていない、割り込みは閉じたまま）。`irq_save` の後の `wq_wait` は、ほかの CPU が条件を変えると起こしを失う。lock の無い語なら `wq_wait_unless`。
- **装置の割り込みはどの CPU にも来る**（`arch/irq.h`：装置の node の中で vector の空いた CPU が受ける。処理は割り込みを閉じた短い hard handler と、要るなら irq の thread。決まった vector を持つ driver は無い）。割り込みの処理と、どの CPU でも走る呼ぶ側が同じ状態に触れるなら、両方が同じ spinlock を取る（呼ぶ側は `spin_lock` で割り込みも閉じる）。周期の拍は無い（`dev/timer.c` は消した）。時間の仕事は、その持ち主が自分の alarm（`sys/alarm.h`、CPU ごとの heap）を立てる。
- **利用者のメモリーは写しだけで触る**（SMAP が止める：`stac` するのは `arch/isr.asm` の `user_copy` だけで、ほかの所の触れは panic）。同じアプリの別の thread がほかの CPU でいつでも頁を外せる。`copy_from_user`／`copy_to_user`・`user_str`・`user_string`（`sys/syscall.h`）は頁違反を戻り値に換え、無い頁を作るので眠ることがある：spinlock の下で呼ばない。`user_ok`／`user_ok_w` は長い仕事の前の確かめだけで、確かめた後に利用者の指を直に読み書きしない（`memcpy` で写さない）。要求の構造体は一度核へ写してから見る。数の多い一覧は核の中に作ってから一度に写す。番地の待ちは物理の番地で読む（`sys/address_wait.c` の `address_read`）。
- lock の順（先に取るもの → 後）：`thread_lock` → 待ち行列の lock → thread の pi lock（優先度の継承、`sys/wait.c`。連なりを辿る一歩だけは次の mutex の待ち行列の lock を `spin_try` で取る）→ 実行キューの lock。事象の行列の lock → object の waiters の lock・番地の bucket の lock → 実行キューの lock、事象の行列の lock → 見張る handle の `watch_lock`・pending の列の `told`（どちらも葉）（`sys/events.c`）。アプリの配置の lock（process の `space.lock`、`sys/syscall.c`）→ `shared_lock` → 頁表の lock → CPU の頁の溜めの lock → node の頁の lock（`mm/pmm.c`）。頁表の lock は空間ごとの `struct vmm_space` の lock と核の半分の `kernel_space.lock`（`mm/vmm.c`）で、二つを同時に持たない。heap（`mm/heap.c`）の depot の lock は葉で、入れ子にせず、その下で頁を確保しない（CPU ごとの鎖は割り込みを閉じて触る）。`mm/vmalloc.c` の lock は葉（その下で他の lock を取らず、確保もしない）で、`vfree` はどの spinlock の下でもよい。**撃ち落とし（TLB）は spinlock の下でも割り込みの処理の中でもしない**：送り手は他の CPU の答えを待つ（`shoot` が `spins_held`・`in_interrupt()` を ASSERT する）。写像を外す・狭める・型を変える呼出し（`vmm_user_free`・`vmm_user_protect`・`vmm_user_write_protect`・`vmm_direct_type`・`vmm_gather_finish`・`vmm_space_end`）がそれに当たり、lock を放してから呼ぶ（例：`sys_shared_view` は `typing` を立てて `shared_lock` を放してから型を変える）。広げる変更（`vmm_map_page`・`vmm_user_alloc`・`vmm_user_reserve`・頁の初めの触れ）は撃たないのでどこからでもよく、古い狭い訳の頁違反は `vmm_fault_spurious` が流す。撃ち落としを待つ CPU は自分の受け箱に答える（`vmm_tlb_poll`）。spinlock を待つ CPU は答えない：持ち主は撃たずに放すので、待ちは錠の分だけ延びる。核の番地を外す道は集め（`vmm_gather_init` → `vmm_kernel_unmap` → `vmm_gather_finish`）で、撃ち落としの後に frame を返す。核の半分の葉は G（CR4.PGE）で、CR3 を書いても消えない：核の番地の写像を外したら必ず撃つ。核の thread は前の空間を CR3 に残して走る（lazy）：利用者の番地に触れない。終わる thread と止まる CPU は `vmm_leave` で空間を離れる。
- handle の表はアプリごと（process の `struct handle_table`、`sys/object.h`）。`handle_get` は錠なしで epoch の区間の中で参照を取り、変更は表ごとの lock（`handle_install` は失敗なら閉じる）。錠なしで読ませる物を外したら、その記憶は `epoch_defer` で返す（`sys/epoch.h`：読む区間は横取りを止めるだけで、眠らず、割り込みの処理の中では読まない）。`thread_list` と process の thread の一覧・親子のつながりは `thread_lock`、空間を外すのも `thread_lock` の下（`sys/process.c` の `process_space_end`、process の `vmm_space` を NULL に）なので、`thread_lock` の下で読んだ `vmm_space` の表はその間は消えない。
- ゲストが止まって見えたら、QEMU の HMP で `info registers -a` を取り、各 CPU の RIP と RBP の鎖（`x /2gx`）を `build/kernel.elf` で llvm-symbolizer に引く。
- カーネルの標本は、起動の cmdline に `prof`（または `prof_ms=<n>`）で有効になり、serial に窓（既定 10 秒）ごとに出る：`prof: cpu%u user … kernel … idle …`、`prof: task pid …`、`prof: <標本数> <rip> pid …`、`prof: switches … wakes … steals …`（実行キューの間の動き）、`prof: TLB …`。起動の cmdline に入れるのは limine の起動の項目を手で編むか、`boot/limine.conf` を変えずに QEMU の起動の画面で。
- 起動の行：`memory: N MiB usable, M MiB free`、`video: monitor … at … Hz`（EDID が決める）、`store: C: "…" on nvme0, …`（SATA の板なら `sata0`）。メモリー切れは `[memory] pid … no pages for …`（10 秒に 1 回まで）。カーネルの行の頭は `[秒.マイクロ秒 CPU:tid]`（時計が動く前は 0、thread の無い行は `-`、重さが INFO でなければ ` E`・` W`・` D`）。記録は CPU ごとの錠の無い輪（`sys/log.c`）で、serial・起動の画面・system log の stream が読む。C: の `AppData\Nocturne\System.log` へ書くのは init の thread。
- 解像度と拍は EDID を変数にして、カーネルと表示経路（`kernel/src/dev/fb.c`、`kernel/src/gui/screenmode.c`、`kernel/src/gui/wm.c`、ドライバー）が決める。limine.conf（resolution、wmrefresh などの cmdline）で固定しない。QEMU では `-device VGA,xres=,yres=` が仮想モニターの EDID。
- 目録（`common/store/catalog.c`）の枝の item 0 の鍵は何も区切らない。目録を変えたら `store tree-test <seed> 200000` を幾つかの種で通す（覚え書き）。
- VM だけの処理の入口は `kernel/src/vm/vm.h` だけ（規則は AGENTS.md「VM の処理は実機の処理と分ける」）。ABI の規則は AGENTS.md「UNIX ではない」。
