# コードを書くとき

読み手は次の Claude である。規則はその性質から来る。60 行、3000 行は目安である。

| Claude の性質 | 決まり |
|---|---|
| 会話をまたいで覚えていない | 知識はコードの近くに置く |
| 読める量に限りがあり、途中で要約される | 部品は一度に読める大きさにする |
| 文字で探す | 名前を一意にし、語を揃える |
| 番号と表からの呼出しは索引に出ない | 間接の呼出しは本物の継ぎ目だけにする |
| 周りを真似る | 悪い例を消し、見本を指定する |
| 文を書くと規則を守った気になる | 規則は機械で確かめる |
| 症状が消えると終わったと思う | 完了を定義する |
| 呼ぶ側が見えないと消すのを怖がる | 消すと組みが呼ぶ側を教える形にする |
| 書き直しは安く、散らばった理解は高い | 継ぎ足さず、部品ごと書き直す |
| 壊すのを恐れて確かめを重ねる | 道具で知り、一度見て進む |

## 規則

1. 整形は `clang-format`。一行に文は一つ。
2. 関数は一つのことをする。60 行を超えたら責務を問う。数合わせで分割しない。
3. 名前は検索で一意にする。一つの物に一つの語を使う。
4. 名前に作業の段の番号、`_new`、`_old`、`_v2` を入れない。
5. 呼出しは名前で書く。関数の表は本物の継ぎ目だけに使う。
6. 型で語る。意味を `int`、`void *`、文字列で運ばない。
7. enum の `switch` に `default` を書かない。増えた値を組みが教える。
8. 道は一つ。古い道、旗の切替、失敗時の代わりの道を持たない。
9. 失敗を隠さない。信頼の境界で全部確かめて理由を返す。
10. 内側の「起きないこと」は `ASSERT` にする。失敗に偽の成功を返さない。
11. コメントはコードに書けないことだけ：仕様の節、錠の順、なぜこの形か。
12. コメントに経緯、作業の段、「まだ」、「〜の持ち主」を書かない。
13. 関数には呼ぶ側、値には読み手、設定には効く先がある。仕事の範囲の中で、無いものは消す。
14. 同じ本体を二か所に置かない。短い関数も写さない。
15. 試験を書くなら、公開の口で、外から見た振る舞いを試す。
16. 試験で内部の関数の本体を切り出さない。コードを消したら試験も消す。
17. 一度きりの確かめは作業場に置く。リポジトリに入れない。

## 悪い形と代わり

| 悪い形 | 代わり |
|---|---|
| 症状の近くに特例を足す | 原因の層で直す |
| 移した後に元の道を残す | 同じ仕事で消す |
| 試験の旗をそのまま設定にする | 試験の旗は試験のカーネルに閉じる |
| 製品の名前を共通コードに書く | 申告で引く |
| 製品を試験の部品に依存させる | 依存を切る |
| 効かないものを窓に出す | 端まで通してから窓に出す |
| 保存の型で窓の部品を決める | 値の意味と人の用事で決める |
| 読み手の無い値や偽の環境で上流を組む | 値を渡す口を作るか、そのコードを外す |
| 警告を切る | 仕事の範囲の中の警告を直す |
| 作業の段を試験の名に残す | 振る舞いの名にする |
