# 部品を作る、移す、消すとき

1. 部品は目的で切る。部品は一つの物か一つの決定を持つ。
2. 状態の書き手は一つ。
3. 依存は一方向。下から上へは事象で知らせる。機械が確かめる。
4. カーネルに入れるのは、権限、割り込み、全プロセスの調停のどれかが要るものだけ。
5. 画面と GPU の汎用の層はカーネルの第一級の部品。窓の管理と合成は、その客のサービス。
6. 決めるのは上、実行は下。決定は純粋な関数にする。
7. 口は小さく型を持つ。外へ見せる見出しは一つ。ほかは `static`。
8. 部品は一回の会話で全部読める大きさにする。3000 行を超えたら責務を問う。
9. 層やサービスを分けるのは、権限、寿命、障害の閉じ込めのどれかを言えるときだけ。
10. 呼ぶ側が一つなら包みを作らない。
11. 製品の名前（NVIDIA、Mesa、virgl、Realtek）はドライバーの中だけに書く。
12. 一つの物は一つの台帳に載る。別の部品は身元で指す。
13. 宣言は一か所に書く。ほかは宣言から生成するか、実行時に引く。
14. 値の間の関係は、その値の持ち主のサービスに書く。窓に書かない。
15. 人に見せるものは人の用事から作る。内部の値を窓へ出さない。
16. 機械が決められるなら聞かない。危ないものは設定にしない。
17. 端から端まで通らない機能は窓に出さず、既定で起こさない。
18. 上流との接着は一か所に集める。上流の語彙を我々の口に持ち込まない。
19. 同じ責務を二つ残さない。古い道を消すまでが一つの変更。
20. 網から来た値を読むコードは権限の無いプロセスで走らせる。網の権限は能力の handle で渡す。

## ハードウェアの抽象化の層（HAL）

機械はどれも同じではない。ハードウェアは HAL の後ろに置く。

1. 装置の種類ごとに契約を一つ持つ：CPU、割り込みと時計、バス、IOMMU、GPU、画面、音、ストレージ、網、入力、USB、電源と温度。
2. 契約の上のコードは、製造者、機種、世代を知らない。
3. 違いは実装の申告で受ける。上は申告で道を選ぶ。
4. 実装は契約の後ろに置く。実装を足しても、呼ぶ側は変わらない。
5. VM の装置も実装の一つ。
6. 契約を最小公倍数にしない。ハードウェアが持つものは、有れば使い切り、無くても動くように作る。
7. 契約の形を一社に合わせない。形は仕様書から作る。
8. 必須の機能の表の行には、それが無いと動かないコードがある。
9. 製造者の違いは製造者ごとの実装に置く。一つのファイルに製造者の分岐を集めない。
