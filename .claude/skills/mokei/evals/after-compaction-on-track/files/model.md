# 目的
- 実機 10 回目：WebGL を使うサイトでブラウザーが落ちる。ログ（USB）を取り出して直す
- 3D Cube：60 Hz では 60 fps で安定、120 / 280 Hz では 55〜60 fps で揺れる。直す
# 形
- 落ちる：Zink → NVK の入口の表（弱い参照）。製品のリンクは遅延メンバー → 済（C73、単位 vulkan_nouveau.o）
- fps：拍を知るのは WM（vblank か モードの周期で合成）。アプリは知らず、cube も rAF も 16 ms の時計で回る
  合成器は BSP の横取りされないスレッドで、合成中はアプリのシステムコールが待たされる
# 今の説明（fps）
1. 60 Hz の 60 は vsync ではなく偶然の位相固定（提出が次の vblank まで寝かされ、合成が cube の起床を押さえる）。
   120/280 Hz では提出の直後に合成 → cube の相対待ちが合成の分だけ延びる → 17・18 ms → 55〜59 fps。
   覆る観測：フレームの拍で回しても 120/280 Hz で揺れる
2. 原因の根：アプリが表示の拍を受け取れず、16 ms（60 Hz の仮定）を自分で刻む。直す場所はここ
# 決めたこと
- WM が窓に「あなたの絵がこのフレームに入った、次を描け」を送る（フレームの拍）。ui.c が UI の出来事にする。
  cube は拍で描き、回転は経過時間で進める（Hz で速さが変わらない）
